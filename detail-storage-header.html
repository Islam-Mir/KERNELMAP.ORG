Intestazioni Storage

📋 INTESTAZIONI STORAGE

DESCRIZIONE:

Le Storage Header gestiscono le strutture dati e i metadati che descrivono l'organizzazione fisica e logica dei dispositivi di storage nel sistema Linux.

CONFRONTO:

Come l'indice e il catalogo di una biblioteca: ogni libro ha la sua scheda con posizione, autore, titolo, ma l'indice generale permette di trovare tutto rapidamente.

🔍 Descrizione Tecnica

Le Storage Header sono le strutture dati fondamentali che descrivono l'organizzazione e le caratteristiche dei dispositivi di storage nel kernel Linux. Immagina un archivio digitale dove ogni cassetto, scaffale e libro ha la sua etichetta precisa con tutte le informazioni necessarie per localizzarlo e gestirlo.

• Block device headers - Strutture per dischi, SSD, dispositivi a blocchi con geometria e parametri

• Partition tables - MBR, GPT per organizzare spazio disco in partizioni

• Filesystem superblocks - Metadati globali per ogni filesystem (ext4, btrfs, xfs)

• Inode tables - Tabelle degli inode con puntatori ai blocchi dati

• Directory structures - Organizzazione gerarchica directory e collegamenti

• Storage metadata - Informazioni su capacità, velocità, stato dispositivi

• Interazione: Forniscono al kernel tutte le informazioni necessarie per gestire storage efficiente

⚙️ Operazioni Principali

Le Storage Header gestiscono quattro aspetti fondamentali dell'organizzazione storage, ciascuno essenziale per l'integrità dei dati:

💾 Block Device Management

• register_blkdev() - Registra un nuovo dispositivo a blocchi

• blkdev_get() - Ottiene riferimento a dispositivo a blocchi

• blkdev_put() - Rilascia riferimento dispositivo

• submit_bio() - Invia richiesta I/O al dispositivo

• blk_queue_max_hw_sectors() - Configura limiti settore dispositivo

📊 Partition Handling

• check_partition() - Verifica validità tabella partizioni

• add_partition() - Aggiunge partizione al sistema

• delete_partition() - Rimuove partizione

• rescan_partitions() - Rilegge tabella partizioni

• hd_struct_init() - Inizializza struttura partizione

🗂️ Filesystem Metadata

• alloc_super() - Alloca struttura superblock

• destroy_super() - Distrugge superblock

• grab_super() - Ottiene riferimento superblock

• drop_super() - Rilascia riferimento superblock

• iterate_supers() - Itera tutti i superblock attivi

📋 Inode Management

• alloc_inode() - Alloca nuova struttura inode

• destroy_inode() - Distrugge inode

• iget_locked() - Ottiene inode bloccato

• iput() - Rilascia riferimento inode

• write_inode_now() - Scrive inode su disco immediatamente

📋 Esempi Pratici

Quando colleghi un nuovo disco al sistema, ecco cosa succede nelle storage headers:

🔍 Rilevamento Dispositivo

1. Il kernel rileva il nuovo dispositivo attraverso il bus (PCI, USB, SATA)

2. Crea una struttura block_device con le informazioni base del dispositivo

3. Legge la partition table (MBR o GPT) per identificare le partizioni

4. Per ogni partizione, determina il tipo di filesystem dal superblock

📄 Strutture Dati Chiave

  • struct block_device - Rappresenta un dispositivo a blocchi con geometria, dimensione e parametri operativi
  • struct hd_struct - Descrive una partizione con inizio, dimensione e numero di settore
  • struct super_block - Contiene metadati globali del filesystem: dimensione, blocchi liberi, parametri di mount
  • struct inode - Rappresenta file e directory con metadati, permessi e puntatori ai dati

💻 Nel Computer: Come Vederlo?

Comandi Linux per esplorare le storage headers:

  • fdisk -l /dev/sda - Mostra la partition table del disco
  • blkid /dev/sda1 - Visualizza informazioni sul filesystem della partizione
  • tune2fs -l /dev/sda1 - Mostra il superblock di un filesystem ext
  • lsblk -f - Elenca dispositivi e filesystem con UUID e LABEL
  • parted /dev/sda print - Mostra dettagliata tabella partizioni

🎯 Caso Reale: Montaggio Disco

Quando fai mount /dev/sdb1 /mnt:

  1. Il kernel valida che /dev/sdb1 è una partizione valida
  2. Legge il superblock per determinare il tipo di filesystem
  3. Alloca strutture inode e dentry per la radice del filesystem
  4. Crea il punto di mount nella directory tree del VFS
  5. Il filesystem diventa accessibile attraverso /mnt

💾 Formati Storage Supportati

  • MBR (Master Boot Record) - Tabella partizioni tradizionale con limite 2TB
  • GPT (GUID Partition Table) - Tabella partizioni moderna con UUID e limiti estesi
  • EXT4 superblock - Metadati filesystem con journaling e extents
  • BTRFS superblock - Filesystem moderno con copy-on-write e snapshot
  • XFS superblock - High-performance con allocation dinamica

✨ Caratteristiche

  • Metadata Integrity - Checksum e journaling per proteggere i metadati
  • Dynamic Updates - Modifiche sicure ai metadati durante l'operazione
  • Backup & Recovery - Superblock backup per disaster recovery
  • Performance Optimization - Cache e prefetching per metadata
  • Compatibility - Supporto per formati legacy e moderni

🔗 Interazioni Chiave

Le storage headers sono il fondamento per tutti i sottosistemi di storage del kernel Linux:

💽 Block Device Layer

• Device registration - Registra dispositivi con le loro caratteristiche geometriche

• Partition scanning - Identifica e valida tabelle partizioni

🗂️ Filesystem Layer

• Superblock management - Gestisce metadati globali del filesystem

• Inode allocation - Assegna e traccia inode per file e directory

🧠 Memory Management

• Page cache coordination - Coordina caching di dati e metadati

• Buffer heads - Gestisce buffer per blocchi di metadati

🔐 Security Framework

• Permission validation - Controlla accessi ai metadati

• Audit logging - Registra operazioni sui metadati critici

⚡ I/O Subsystem

• Request queuing - Accoda richieste I/O per metadata

• Writeback coordination - Sincronizza modifiche ai metadati

🛠️ API Principali

Queste sono le funzioni chiave per gestire le storage headers nel kernel Linux:

💽 Block Device Management

int register_blkdev(unsigned int major, const char *name);
Registra un nuovo major number per dispositivi a blocchi.

struct block_device *blkdev_get_by_path(const char *path, fmode_t mode, void *holder);
Ottiene un riferimento a un dispositivo a blocchi dal path.

void blkdev_put(struct block_device *bdev, fmode_t mode);
Rilascia un riferimento a un dispositivo a blocchi.

📊 Partition Management

int rescan_partitions(struct gendisk *disk, struct block_device *bdev);
Rilegge la tabella partizioni di un disco.

struct hd_struct *add_partition(struct gendisk *disk, int partno, sector_t start, sector_t len, int flags, struct partition_meta_info *info);
Aggiunge una nuova partizione al sistema.

void delete_partition(struct gendisk *disk, int partno);
Rimuove una partizione dal sistema.

🗂️ Filesystem Metadata

struct super_block *alloc_super(struct file_system_type *type, int flags, const char *dev_name);
Alloca una nuova struttura superblock per un filesystem.

void destroy_super(struct super_block *s);
Distrugge una struttura superblock.

struct inode *alloc_inode(struct super_block *sb);
Alloca un nuovo inode per il filesystem.

🔍 Esempi di Utilizzo Quotidiano

Quando colleghi un nuovo disco USB:

  1. register_blkdev() - Registra il nuovo dispositivo a blocchi
  2. rescan_partitions() - Scansiona la tabella partizioni
  3. alloc_super() - Crea superblock per ogni partizione
  4. alloc_inode() - Alloca inode per la radice del filesystem
  5. Il disco diventa accessibile nel sistema

Le storage headers rendono possibile l'accesso strutturato a tutti i dispositivi di storage!

🎬 Demo Interattiva: Come Funzionano le Storage Headers

💻 Simulazione: Montaggio di un nuovo disco

💿 Nuovo Disco
/dev/sdb (2TB HDD)
(disco appena collegato)
📋
🗂️ Filesystem Montato
/mnt/data (ext4)
(accessibile nel sistema)
Comandi eseguiti: fdisk /dev/sdb → mkfs.ext4 /dev/sdb1 → mount /dev/sdb1 /mnt/data

🔄 Cosa succede dietro le quinte:

  1. 1. Rilevamento dispositivo: Kernel registra il nuovo block device con register_blkdev()
  2. 2. Creazione partizione: fdisk scrive la tabella partizioni (MBR/GPT) sul disco
  3. 3. Formattazione: mkfs.ext4 crea superblock, inode table, e strutture dati ext4
  4. 4. Montaggio: mount() legge superblock, valida filesystem, crea punto di mount
  5. 5. Accessibilità: Il disco diventa parte del namespace del sistema
🎯 Risultato: Da disco grezzo a filesystem montato! Le storage headers rendono possibile l'organizzazione strutturata dei dati su qualsiasi dispositivo!

🎯 Concetti Chiave da Ricordare

📋

Gerarchia dei Metadati

Block device → Partition table → Superblock → Inode table → Data blocks. Ogni livello aggiunge struttura e organizzazione.

🛡️

Integrità Critica

Corruption dei metadati può rendere inaccessibili tutti i dati. Backup multipli e checksum proteggono l'integrità.

🔄

Aggiornamenti Dinamici

Le storage headers vengono aggiornate durante l'operazione normale. Il journaling garantisce atomicità delle modifiche.

🔧

Recovery & Backup

Superblock backup e tool di recovery permettono di ricostruire l'accesso ai dati anche dopo corruption grave.
