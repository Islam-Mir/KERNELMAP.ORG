🖱️ PERIFERICHE UTENTE

DESCRIZIONE:

I User Peripherals rappresentano l'insieme dei dispositivi di input/output che gli utenti utilizzano direttamente per interagire con il sistema Linux. Questo sottosistema gestisce tastiere, mouse, touchscreen, webcam, microfoni, altoparlanti e altri dispositivi che permettono l'interazione umana con il computer attraverso interfacce standardizzate.

CONFRONTO:

Immagina i User Peripherals come i sensi di un organismo vivente: la tastiera e il mouse sono le "mani" per dare comandi, lo schermo è la "vista" per ricevere feedback, gli altoparlanti sono l'"udito" per suoni e notifiche, creando un'interfaccia completa tra uomo e macchina.

🔍 Descrizione Tecnica

I User Peripherals implementano driver e protocolli specializzati per dispositivi di interfaccia umana, utilizzando framework come Input Subsystem, ALSA per audio, V4L2 per video, e DRM per grafica. Ogni categoria di dispositivo ha API specifiche ottimizzate per prestazioni real-time e bassa latenza.

• Input Devices - Gestione eventi da tastiere, mouse, touchscreen con supporto multitouch

• Audio Devices - Cattura e riproduzione audio con mixing e effetti in tempo reale

• Video Devices - Webcam e dispositivi di cattura video con supporto compressione

• Interfaccia principale tra dispositivi fisici e applicazioni userspace

⚙️ Operazioni Principali dei User Peripherals

I User Peripherals gestiscono operazioni specializzate per dispositivi di interfaccia umana:

⚙️ Input Device Operations

• input_event() - Invia eventi input (tasto premuto, movimento mouse)

• input_register_device() - Registra nuovo dispositivo input nel sistema

• input_allocate_device() - Alloca struttura per nuovo dispositivo input

⚙️ Audio Operations

• snd_pcm_writei() - Scrive dati audio PCM interleaved

• snd_pcm_readi() - Legge dati audio PCM interleaved

• snd_mixer_selem_set_playback_volume() - Imposta volume di riproduzione

⚙️ Video Operations

• ioctl(VIDIOC_STREAMON) - Avvia streaming video dalla webcam

• ioctl(VIDIOC_QBUF) - Accoda buffer per cattura video

• ioctl(VIDIOC_S_FMT) - Imposta formato video (risoluzione, pixel format)

⚙️ Graphics Operations

• drmModeSetCrtc() - Configura controller RAMDAC per display

• drm_gem_create() - Crea oggetto memoria grafica

• drm_fb_create() - Crea framebuffer per display

📋 Esempi Pratici dei User Peripherals

I User Peripherals rendono possibile l'interazione umana completa con il sistema Linux:

🔍 Digitazione su Tastiera

1. Utente preme tasto 'A' sulla tastiera

2. Controller tastiera genera interrupt e invia scancode

3. Driver input converte scancode in keycode e invia evento

4. Xorg riceve evento e aggiorna display con lettera 'A'

📄 Strutture Dati Chiave

  • input_dev - Struttura principale dispositivo input (tastiera, mouse)
  • snd_pcm_substream - Sottostream audio PCM per playback/capture
  • v4l2_device - Dispositivo V4L2 per webcam e dispositivi video
  • drm_device - Dispositivo DRM per schede grafiche
  • fb_info - Informazioni framebuffer per display diretto

  • $ xinput list - Lista dispositivi input Xorg

🎯 Caso Reale: Videochiamata

Quando fai una videochiamata con $ skype:

🛠️ API dei User Peripherals

Le API dei User Peripherals forniscono controllo diretto sui dispositivi di interfaccia umana:

📂 Input Device API

int open(const char *pathname, int flags);
Apre dispositivo input (/dev/input/event0) per lettura eventi.

ssize_t read(int fd, struct input_event *events, size_t count);
Legge eventi input (tasti, movimento mouse) dal dispositivo.

int ioctl(int fd, EVIOCGRAB, int grab);
Cattura esclusivamente eventi da dispositivo (grab input).

int ioctl(int fd, EVIOCGNAME, char *name);
Ottiene nome descrittivo del dispositivo input.

📊 Audio API (ALSA)

int snd_pcm_open(snd_pcm_t **pcm, const char *name, snd_pcm_stream_t stream, int mode);
Apre dispositivo PCM per playback o capture audio.

int snd_pcm_set_params(snd_pcm_t *pcm, snd_pcm_format_t format, snd_pcm_access_t access, unsigned int channels, unsigned int rate, int soft_resample, unsigned int latency);
Configura parametri hardware del dispositivo audio.

snd_pcm_sframes_t snd_pcm_writei(snd_pcm_t *pcm, const void *buffer, snd_pcm_uframes_t size);
Scrive campioni audio interleaved nel dispositivo.

💽 Video API (V4L2)

int ioctl(int fd, VIDIOC_QUERYCAP, struct v4l2_capability *cap);
Ottiene capacità del dispositivo video (webcam).

int ioctl(int fd, VIDIOC_S_FMT, struct v4l2_format *fmt);
Imposta formato video (risoluzione, pixel format).

int ioctl(int fd, VIDIOC_STREAMON, int *type);
Avvia cattura video dalla webcam.

🔍 Esempi di Utilizzo Pratico

Come utilizzare le API dei User Peripherals nelle applicazioni:

  1. open("/dev/input/event0", O_RDONLY) - Apri dispositivo tastiera per lettura eventi
  2. snd_pcm_open(&handle, "default", SND_PCM_STREAM_PLAYBACK, 0) - Apri dispositivo audio
  3. ioctl(fd, VIDIOC_S_FMT, &fmt) - Configura formato video webcam
  4. read(input_fd, &event, sizeof(event)) - Leggi evento input (tasto premuto)

Queste API forniscono controllo diretto sui dispositivi di interfaccia umana con prestazioni ottimali.

🎬 Funzionamento dei User Peripherals

💻 Come funzionano i dispositivi di interfaccia utente

📥 Evento Hardware
Utente interagisce con dispositivo (preme tasto, muove mouse)
⚡
⚙️ Elaborazione Kernel
Driver cattura evento, lo elabora e lo inoltra al sottosistema appropriato
Processo eseguito: I User Peripherals ricevono eventi hardware grezzi dai dispositivi fisici, li elaborano attraverso driver specializzati, li astraggono in eventi di alto livello e li consegnano alle applicazioni userspace attraverso API standardizzate, garantendo isolamento e prestazioni ottimali.

🔄 Ciclo di vita di un evento periferica:

  1. 1. Hardware Interrupt - Dispositivo genera interrupt su evento (tasto premuto)
  2. 2. Driver Capture - Driver specifico cattura dati grezzi dall'hardware
  3. 3. Event Processing - Conversione in evento standardizzato (input_event)
  4. 4. Subsystem Routing - Inoltro al sottosistema appropriato (input, ALSA, V4L2)
  5. 5. Userspace Delivery - Consegna all'applicazione attraverso device file
  6. 6. Application Response - Applicazione elabora evento e aggiorna interfaccia
🎯 Risultato: L'utente ottiene un'interfaccia fluida e responsiva con tutti i dispositivi di input/output, indipendentemente dall'hardware sottostante.

🔬 Esperimenti da fare sul tuo Linux

⌨️ Monitora eventi input

$ cat /proc/bus/input/devices
I: Bus=0011 Vendor=0001 Product=0001
N: Name="AT Translated Set 2 keyboard"

$ evtest /dev/input/event0

Esplora dispositivi input e monitora eventi in tempo reale

🔊 Test audio ALSA

$ aplay -l
**** List of PLAYBACK Hardware Devices ****
card 0: PCH [HDA Intel PCH], device 0

$ speaker-test -c 2 -t sine

Lista dispositivi audio e testa output con segnale sinusoidale

📹 Scopri dispositivi video

$ v4l2-ctl --list-devices
Integrated Camera (usb-0000:00:14.0-8):
/dev/video0

$ v4l2-ctl --list-formats

Identifica webcam e dispositivi video con formati supportati

🖼️ Info accelerazione grafica

$ glxinfo | grep renderer
OpenGL renderer string: Mesa Intel(R)

$ ls /dev/dri/

Verifica supporto OpenGL e dispositivi DRI disponibili
