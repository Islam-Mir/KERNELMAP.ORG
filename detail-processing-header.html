PROCESSING HEADER

Intestazioni di Elaborazione

📋 INTESTAZIONI ELABORAZIONE

DESCRIZIONE:

Le Processing Header gestiscono le strutture dati e i metadati che descrivono l'organizzazione e lo stato dei processi e thread nel sistema operativo Linux.

CONFRONTO:

Come il registro di classe di una scuola: ogni alunno (processo) ha la sua scheda con nome, voti, presenze, ma il registro generale permette di organizzare tutto e trovare rapidamente le informazioni.

🔍 Descrizione Tecnica

Le Processing Header sono le strutture dati fondamentali che descrivono l'organizzazione e le caratteristiche dei processi e thread nel kernel Linux. Immagina un grande schedario digitale dove ogni processo ha la sua cartella con tutte le informazioni necessarie: stato, risorse allocate, relazioni con altri processi, priorità, e tutto ciò che serve per gestirlo correttamente.

• Process descriptors - Strutture task_struct con tutte le info sui processi

• Thread info blocks - Informazioni specifiche per ogni thread

• Process hierarchy - Relazioni padre-figlio tra processi

• Resource tracking - Monitoraggio risorse allocate per processo

• Scheduling parameters - Priorità, nice values, scheduling class

• Security contexts - Contesti di sicurezza per ogni processo

• Interazione: Forniscono al kernel tutte le informazioni necessarie per schedulare e gestire processi

⚙️ Operazioni Principali

Le Processing Header gestiscono quattro aspetti fondamentali dell'organizzazione processi, ciascuno essenziale per il multitasking:

🔄 Process Creation

• alloc_task_struct() - Alloca struttura task_struct per nuovo processo

• copy_process() - Copia informazioni processo padre nel figlio

• wake_up_new_task() - Riattiva processo appena creato

• dup_task_struct() - Duplica struttura task per fork

• free_task_struct() - Libera struttura processo terminato

🎯 Scheduling Management

• task_fork_fair() - Inizializza scheduler CFS per nuovo task

• set_user_nice() - Imposta priorità nice del processo

• sched_setscheduler() - Cambia politica scheduling

• task_tick_fair() - Aggiorna contatori scheduler ad ogni tick

• pick_next_task() - Seleziona prossimo task da eseguire

💾 Resource Tracking

• get_task_mm() - Ottiene puntatore allo spazio memoria

• get_task_cred() - Ottiene credenziali sicurezza processo

• task_lock() - Blocca struttura task per modifiche

• task_unlock() - Sblocca struttura task

• find_task_by_pid() - Trova processo per PID

🛡️ Security Context

• prepare_creds() - Prepara nuove credenziali per processo

• commit_creds() - Applica nuove credenziali

• override_creds() - Sostituisce credenziali temporaneamente

• revert_creds() - Ripristina credenziali originali

• validate_creds() - Valida correttezza credenziali

📋 Esempi Pratici

Esempi concreti di strutture dati per processi nel kernel Linux:

🔍 Creazione di un Nuovo Processo

Quando lanci un comando come ls:

  • fork() - Crea nuovo task_struct copiando quello del padre
  • execve() - Sostituisce l'immagine del processo con ls
  • Il kernel aggiorna PID, PPID, e altre strutture del processo
  • Lo scheduler aggiunge il processo alla runqueue

📄 Strutture Dati Chiave

  • task_struct - Struttura principale con PID, stato, priorità, credenziali
  • thread_info - Informazioni specifiche del thread (flags, CPU, preempt)
  • sched_entity - Parametri di scheduling (vruntime, load, priority)
  • mm_struct - Gestione dello spazio di memoria virtuale
  • files_struct - Tabella dei file descriptor aperti
  • signal_struct - Gestione segnali e loro handlers

💻 Nel Computer: Come Vederlo?

Comandi Linux per esplorare le strutture processi:

  • ps aux - Mostra PID, PPID, stato, comando di tutti i processi
  • cat /proc/$$/status - Stato dettagliato del processo corrente
  • cat /proc/$$/sched - Parametri di scheduling del processo
  • pstree - Visualizza la gerarchia padre-figlio dei processi
  • top -p $$ - Monitora risorse usate dal processo

🎯 Caso Reale: Multitasking

Quando il sistema esegue più programmi contemporaneamente:

  1. Ogni processo ha il suo task_struct con priorità e stato
  2. Lo scheduler CFS mantiene vruntime per fairness
  3. Context switch salva/restaura registri e stack
  4. Il kernel alterna esecuzione tra processi runnable
  5. Interrupt possono preemptare processi in esecuzione

⚙️ Modelli di Scheduling Supportati

  • CFS (Completely Fair Scheduler) - Scheduler predefinito basato su fairness e vruntime
  • Real-time scheduling - SCHED_FIFO e SCHED_RR per processi real-time
  • Deadline scheduling - SCHED_DEADLINE per vincoli temporali rigorosi
  • Nice values - Sistema di priorità relativa da -20 a +19
  • Control Groups (cgroups) - Limitazione risorse per gruppi di processi

✨ Caratteristiche

  • Modularità - Strutture dati estensibili per nuove funzionalità
  • Efficienza - Layout ottimizzato per cache CPU e accesso rapido
  • Sicurezza - Separazione credenziali e controllo accessi granulare
  • Scalabilità - Supporto per sistemi con migliaia di processi
  • Real-time capable - Supporto per scheduling real-time deterministico

🔗 Interazioni Chiave

Le processing header interagiscono con tutti i principali sottosistemi del kernel:

⚙️ Scheduler Subsystem

• CFS scheduler - Usa vruntime e load balancing per decisioni di scheduling

• Real-time scheduler - Gestisce processi con priorità assoluta

• Load balancer - Distribuisce processi tra CPU disponibili

🧠 Memory Management

• Virtual memory - Gestisce spazi di indirizzamento per processi

• Page tables - Traduce indirizzi virtuali in fisici

• Memory limits - Applica limiti RAM per processo

🔌 Interrupt System

• Context switching - Salva/restaura stato durante switch processi

• Preemption - Permette interruzione processi per priorità più alta

• Timer interrupts - Gestisce time slice e scheduling periodico

🔐 Security Framework

• Credentials - Gestisce UID, GID, capabilities per processo

• Namespaces - Isola processi in ambienti separati

• Capabilities - Permessi granulari oltre il modello root/non-root

📡 IPC Subsystem

• Signals - Meccanismo di comunicazione asincrona tra processi

• Pipes/FIFOs - Comunicazione unidirezionale tra processi

• Shared memory - Memoria condivisa per comunicazione veloce

🛠️ API Principali

Queste sono le funzioni kernel per gestire processi e scheduling:

⚙️ Gestione Processi

struct task_struct *current;
Macro che restituisce il puntatore al processo attualmente in esecuzione.

pid_t task_pid_nr(struct task_struct *tsk);
Restituisce il PID di un processo dato il suo task_struct.

struct task_struct *find_task_by_pid(pid_t pid);
Trova un processo nella hash table usando il suo PID.

void wake_up_process(struct task_struct *tsk);
Riattiva un processo dormiente mettendolo nella runqueue.

🎯 Scheduling Operations

void schedule(void);
Funzione principale dello scheduler che seleziona il prossimo processo da eseguire.

int sched_setscheduler(pid_t pid, int policy, struct sched_param *param);
Imposta la politica di scheduling per un processo (CFS, RT, deadline).

int set_user_nice(struct task_struct *p, long nice);
Modifica il valore nice di un processo per regolare la sua priorità.

🔐 Security Context

const struct cred *get_task_cred(struct task_struct *task);
Ottiene le credenziali di sicurezza di un processo (UID, GID, capabilities).

int capable(int cap);
Verifica se il processo corrente ha una specifica capability.

void put_cred(const struct cred *cred);
Rilascia il riferimento alle credenziali ottenuto con get_task_cred.

🔍 Esempi di Utilizzo Quotidiano

Quando il kernel decide di cambiare processo:

  1. schedule() - Scheduler seleziona il prossimo processo runnable
  2. context_switch() - Salva stato corrente, carica nuovo processo
  3. switch_mm() - Cambia tabelle delle pagine per nuovo spazio memoria
  4. switch_to() - Salta all'entry point del nuovo processo

Ogni context switch coinvolge le processing header per salvare e ripristinare lo stato del processo!

🎬 Demo Interattiva: Context Switching

💻 Simulazione: Cambio di processo nel kernel

⚙️ Processo A (bash)
PID: 1234
Stato: RUNNING
(in esecuzione sulla CPU)
🔄
📊 Processo B (firefox)
PID: 5678
Stato: READY
(pronto per esecuzione)
Evento scatenante: Timer interrupt ogni 4ms

🔄 Sequenza del context switch:

  1. 1. Interrupt handler: CPU salva stato corrente in thread_info
  2. 2. Scheduler invocation: schedule() seleziona prossimo processo
  3. 3. Context save: Salva registri e stack pointer in task_struct
  4. 4. Memory switch: Cambia tabelle pagine per nuovo spazio memoria
  5. 5. Context restore: Carica registri e stack del nuovo processo
  6. 6. Resume execution: Nuovo processo continua dall'istruzione successiva
🎯 Risultato: L'utente percepisce multitasking continuo, ma il kernel alterna rapidamente tra processi usando le processing header per salvare e ripristinare lo stato!

🎯 Concetti Chiave da Ricordare

📋

Task Struct Core

task_struct è il cuore delle processing header. Contiene tutto ciò che il kernel deve sapere su un processo: stato, priorità, risorse, sicurezza.

⚡

Context Switching

Il cambio di contesto è l'operazione più costosa del kernel. Le processing header ottimizzano il salvataggio e ripristino dello stato dei processi.

🎯

Scheduling Entity

sched_entity contiene i parametri di scheduling: vruntime, load, priorità. È ciò che il CFS scheduler usa per prendere decisioni.

🔐

Security Context

Ogni processo ha credenziali (UID/GID), capabilities, e namespace. Le processing header garantiscono isolamento e controllo accessi.
