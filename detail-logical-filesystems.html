💽 FILESYSTEM LOGICI

DESCRIZIONE:

I Logical Filesystems rappresentano l'implementazione concreta dei filesystem nel kernel Linux, fornendo le operazioni effettive di lettura/scrittura sui dispositivi di storage attraverso interfacce standardizzate.

CONFRONTO:

Come i diversi motori di un'auto: ognuno ha il suo funzionamento interno (benzina, diesel, elettrico), ma tutti si collegano allo stesso sistema di trasmissione per muovere il veicolo. I filesystem logici sono i "motori" che convertono le richieste astratte del VFS in operazioni concrete sui dischi.

🔍 Descrizione Tecnica

I Logical Filesystems sono le implementazioni concrete che trasformano le operazioni astratte del Virtual File System in azioni specifiche sui dispositivi fisici. Immagina di avere un ristorante dove il maître (VFS) prende le ordinazioni, ma sono i cuochi (filesystem logici) che preparano effettivamente i piatti usando ingredienti specifici (blocchi del disco).

• Implementazione specifica del filesystem - Ogni filesystem (EXT4, BTRFS, XFS) ha la sua logica interna per gestire file e directory

• Gestione strutture su disco - Organizzazione fisica dei dati, metadati, journaling e strutture di recovery

• Ottimizzazioni specifiche - Algoritmi ottimizzati per il tipo di storage e le caratteristiche del filesystem

• Interazione: Ricevono richieste dal VFS e le eseguono sui dispositivi di storage sottostanti

⚙️ Operazioni Principali

I Logical Filesystems gestiscono quattro categorie fondamentali di operazioni che trasformano le richieste astratte in azioni concrete sul disco:

📁 File Operations

• create() - Crea nuovi file allocando inode e strutture dati appropriate

• unlink() - Rimuove file liberando spazio e aggiornando strutture di directory

• truncate() - Modifica dimensione del file liberando o allocando blocchi

📂 Directory Operations

• mkdir() - Crea directory con entry "." e ".." appropriate

• rmdir() - Rimuove directory vuote e aggiorna strutture padre

• rename() - Sposta/rinomina file o directory mantenendo integrità

💾 Space Management

• alloc_blocks() - Alloca blocchi liberi per nuovi dati o metadati

• free_blocks() - Rilascia blocchi non più utilizzati

• resize_fs() - Ridimensiona il filesystem (online resize)

🔄 Journaling & Recovery

• journal_start() - Inizia transazione journaled per atomicità

• journal_commit() - Conferma transazione e aggiorna strutture permanenti

• fsck() - Verifica e ripara inconsistenze del filesystem

📋 Esempi Pratici

Quando crei un file con 'touch nuovo.txt', ecco cosa succede nei Logical Filesystems:

🔍 Creazione di un Nuovo File

1. Il VFS riceve la richiesta e chiama la funzione create() del filesystem (EXT4)

2. EXT4 cerca un inode libero nella inode table del disco

3. Alloca blocchi per i dati iniziali e aggiorna le strutture di directory

4. Scrive le modifiche nel journal per garantire atomicità

📄 Strutture Dati Chiave

  • ext4_inode - Struttura che contiene tutti i metadati di un file EXT4 (permessi, dimensione, puntatori ai blocchi)
  • ext4_super_block - Contiene informazioni globali del filesystem (dimensione, blocchi liberi, parametri di tuning)
  • journal_t - Gestisce il journaling per garantire consistenza dopo crash
  • ext4_extent - Struttura per gestire allocazione contigua di blocchi ( extents )

💻 Comandi Linux per Esplorare

  • tune2fs -l /dev/sda1 - Mostra il superblock e parametri del filesystem EXT4
  • debugfs /dev/sda1 - Esplora strutture interne del filesystem in modo interattivo
  • dumpe2fs /dev/sda1 - Mostra informazioni dettagliate su gruppi di blocchi e inode
  • fsck.ext4 -f /dev/sda1 - Verifica e ripara inconsistenze del filesystem

🎯 Caso Reale: Scrittura di un File

Quando salvi un documento:

  1. Il filesystem alloca extents contigui per i nuovi dati
  2. I dati vengono scritti nei blocchi allocati
  3. Le modifiche ai metadati vengono registrate nel journal
  4. Il journal viene committato per rendere permanenti le modifiche

💾 Filesystem Supportati

  • EXT4 - Filesystem nativo Linux con extents, journaling e prestazioni elevate
  • BTRFS - Moderno filesystem con snapshot, checksum e compressione integrata
  • XFS - High-performance journaling filesystem ottimizzato per grandi storage
  • ZFS - Advanced filesystem con storage pooling e deduplicazione
  • F2FS - Ottimizzato per dispositivi flash (SSD, eMMC)

✨ Caratteristiche

  • Journaling - Garantisce consistenza del filesystem dopo crash o interruzioni improvvise
  • Extents - Allocazione contigua di blocchi per prestazioni migliori
  • Online resize - Possibilità di ridimensionare filesystem mentre sono montati
  • Snapshot - Creazione di istantanee del filesystem per backup e recovery

🔗 Interazioni Chiave

I Logical Filesystems sono il ponte tra il mondo astratto del VFS e la realtà fisica dello storage, interagendo con molteplici componenti del sistema:

💽 Virtual File System (VFS)

• Operation dispatch - Riceve chiamate dal VFS e le instrada alle funzioni specifiche del filesystem

• Object registration - Registra strutture dati (inode, superblock) nel VFS layer

💾 Block Layer

• I/O requests - Invia richieste di lettura/scrittura al block layer per accesso ai dispositivi

• Buffer management - Coordina con il buffer cache per ottimizzare accessi al disco

🧠 Memory Management

• Page cache - Collabora con il page cache per mantenere dati in RAM

• Address space - Gestisce address_space per file memory-mapped

⚡ Journaling Subsystem

• Transaction management - Utilizza il journaling per garantire atomicità delle operazioni

• Recovery coordination - Coordina il recovery dopo crash o interruzioni

🛠️ API Principali

Queste sono le funzioni chiave che ogni filesystem implementa per fornire le operazioni concrete richieste dal VFS:

📂 File Operations

struct dentry *ext4_lookup(struct inode *dir, struct dentry *dentry, unsigned int flags);
Cerca un file in una directory EXT4 e restituisce il dentry corrispondente.

int ext4_create(struct inode *dir, struct dentry *dentry, umode_t mode, bool excl);
Crea un nuovo file regolare nella directory specificata.

ssize_t ext4_readpage(struct file *file, struct page *page);
Legge una pagina di dati dal disco nel page cache.

int ext4_writepage(struct page *page, struct writeback_control *wbc);
Scrive una pagina modificata dal page cache al disco.

📊 Inode Operations

int ext4_getattr(const struct path *path, struct kstat *stat, u32 request_mask, unsigned int query_flags);
Ottiene attributi del file (dimensione, permessi, timestamp).

int ext4_setattr(struct dentry *dentry, struct iattr *attr);
Modifica attributi del file (permessi, dimensione, ownership).

int ext4_truncate(struct inode *inode);
Tronca o estende un file alla dimensione specificata.

💽 Superblock Operations

int ext4_fill_super(struct super_block *sb, void *data, int silent);
Inizializza la struttura super_block leggendo dal disco.

int ext4_sync_fs(struct super_block *sb, int wait);
Sincronizza metadati del filesystem con il disco.

🔍 Esempi di Utilizzo Quotidiano

Quando usi comandi come mkfs, mount o fsck, stai interagendo direttamente con i logical filesystems:

  1. mkfs.ext4 /dev/sdb1 - Crea un nuovo filesystem EXT4 sul dispositivo
  2. mount /dev/sdb1 /mnt/data - Monta il filesystem nel sistema
  3. df -T - Mostra tipi di filesystem montati

Il risultato è che dispositivi di storage grezzi diventano filesystem utilizzabili con directory, file e permessi

🎬 Demo Interattiva: Creazione di un File EXT4

💻 Simulazione: Scrittura di un file su EXT4

📝 Richiesta Scrittura
echo "ciao" > file.txt
(Comando shell)
⚡
💽 EXT4 Filesystem
ext4_writepage()
(Implementazione concreta)
Comando osservato: strace -e write echo "ciao" > file.txt

🔄 Sequenza di scrittura EXT4:

  1. 1. VFS dispatch - Il VFS riceve la richiesta e chiama ext4_writepage()
  2. 2. Journal start - Inizia una transazione journaled per garantire atomicità
  3. 3. Extent allocation - Alloca extents contigui per i nuovi dati
  4. 4. Data write - Scrive i dati nei blocchi allocati
  5. 5. Metadata update - Aggiorna inode con nuova dimensione e timestamp
  6. 6. Journal commit - Conferma la transazione rendendo permanenti le modifiche
🎯 Risultato: Il file viene creato sul disco con strutture EXT4 ottimizzate, pronto per essere letto o modificato in futuro.

🎯 Concetti Chiave da Ricordare

📝

Journaling

Il journaling garantisce che le operazioni del filesystem siano atomiche. Come una transazione bancaria: o tutto riesce o tutto viene annullato, proteggendo da crash improvvisi.

📏

Extents

Gli extents allocano blocchi contigui per file, migliorando prestazioni e riducendo frammentazione. È come prenotare posti consecutivi in un teatro invece che sparsi.

🔄

Copy-on-Write

Usato in BTRFS, copia i dati solo quando vengono modificati. Come lavorare su una fotocopia invece che sull'originale, preservando la versione precedente.

📸

Snapshot

Istantanee del filesystem che catturano lo stato in un momento preciso. Come una fotografia: puoi tornare indietro nel tempo senza perdere i dati correnti.
