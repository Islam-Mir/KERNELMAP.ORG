PAGE CACHE

Cache delle Pagine

📄 CACHE PAGINE

DESCRIZIONE:

La Page Cache è il sistema di caching intelligente che mantiene in memoria RAM le pagine di dati più frequentemente utilizzate, riducendo drasticamente gli accessi al disco.

CONFRONTO:

Come una biblioteca personale: i libri più letti (dati più usati) vengono tenuti sulla scrivania (RAM) invece che negli scaffali (disco), permettendo accessi immediati senza dover cercare ogni volta.

🔍 Descrizione Tecnica

La Page Cache è il meccanismo di caching più importante del kernel Linux, mantenendo in memoria le pagine di dati più frequentemente accedute per ridurre drasticamente la latenza di I/O. Immagina un magazziniere intelligente che anticipa le richieste: tiene sempre a portata di mano gli articoli più popolari, riducendo i tempi di consegna da minuti a millisecondi.

• Read-ahead prediction - Pre-carica pagine anticipate che probabilmente saranno richieste

• Write-back buffering - Accumula scritture per scrivere in batch ottimizzati

• LRU page replacement - Algoritmi per decidere quali pagine mantenere in cache

• Dirty page tracking - Traccia pagine modificate da sincronizzare su disco

• Page reference counting - Gestisce condivisione pagine tra processi

• Memory pressure handling - Riduce cache sotto pressione di memoria

• Interazione: Coordina tra VFS, memory manager e dispositivi storage per prestazioni ottimali

📋 Esempi Pratici

Quando apri un file come /home/user/documento.txt, ecco cosa succede nella page cache:

🔍 Cache Hit vs Cache Miss

1. Il kernel cerca la pagina richiesta nella page cache usando l'address_space

2. Se trova la pagina (cache hit), la restituisce immediatamente dalla RAM

3. Se non trova (cache miss), genera un page fault e carica la pagina dal disco

4. La pagina caricata viene aggiunta alla cache per accessi futuri

📄 Strutture Dati Chiave

  • struct page - Rappresenta una singola pagina fisica da 4KB contenente dati dalla cache
  • address_space - Mantiene il mapping tra offset del file e pagine in cache
  • radix_tree - Struttura dati efficiente per cercare pagine per offset
  • page flags - Bit che indicano stato (dirty, uptodate, locked, etc.)

💻 Nel Computer: Come Vederlo?

Comandi Linux per esplorare la page cache:

  • cat /proc/meminfo | grep -E "(Cached|Dirty|Writeback)" - Statistiche cache
  • vmstat -s | grep "pages" - Pagine in vari stati
  • free -h - Memoria totale e cached
  • slabtop | grep page - Uso memoria per strutture page
  • perf stat -e cache-misses ./program - Monitora miss della cache

🎯 Caso Reale: Lettura File Grande

Quando fai cat /var/log/syslog:

  1. Il kernel inizia a leggere dalla page cache
  2. Prime pagine: cache miss → caricamento da disco
  3. Pagine successive: spesso cache hit → lettura da RAM
  4. Read-ahead carica pagine anticipate in background
  5. Il file sembra "istantaneo" grazie alla cache

💾 Tipi di Page Cache

  • File-backed cache - Cache per file regolari mappati su disco
  • Anonymous pages - Pagine di memoria senza file sottostante (heap, stack)
  • Shared memory - Pagine condivise tra processi (System V, POSIX)
  • Memory-mapped files - File mappati direttamente in memoria virtuale
  • Buffer cache - Cache per metadata del filesystem (deprecata)

✨ Caratteristiche

  • LRU eviction - Least Recently Used per rimuovere pagine meno usate
  • Write-back - Scrittura differita per prestazioni ottimali
  • Read-ahead - Precaricamento intelligente di pagine
  • Dirty tracking - Monitoraggio pagine modificate da sincronizzare
  • Pressure handling - Riduzione automatica sotto pressione memoria

🔗 Interazioni Chiave

La page cache è il cuore del sistema di I/O del kernel Linux, interagendo con tutti i principali sottosistemi:

💽 Block Device Layer

• Request submission - Invia richieste I/O per pagine mancanti

• Completion handling - Riceve dati e aggiorna pagine in cache

🗂️ Virtual File System

• Address space operations - Coordina caricamento pagine per file

• Inode integration - Connette cache alle strutture inode

🧠 Memory Management

• Page allocation - Richiede pagine fisiche per la cache

• Reclaim pressure - Riduce cache sotto pressione di memoria

⚙️ Process Scheduler

• Page fault handling - Gestisce fault per pagine non in cache

• Context switching - Mantiene cache durante cambi processo

⚡ I/O Subsystem

• Writeback threads - Sincronizza pagine dirty su disco

• Read-ahead - Precarica pagine anticipate

🛠️ API Principali

Queste sono le funzioni chiave per gestire la page cache nel kernel Linux:

📖 Cache Operations

struct page *find_get_page(struct address_space *mapping, pgoff_t offset);
Trova una pagina nella cache per l'offset specificato.

struct page *page_cache_alloc(struct address_space *mapping);
Alloca una nuova pagina per la cache.

void add_to_page_cache(struct page *page, struct address_space *mapping, pgoff_t offset);
Aggiunge una pagina alla cache per un address space.

✏️ Write Operations

void set_page_dirty(struct page *page);
Marca una pagina come modificata (dirty).

int write_cache_pages(struct address_space *mapping, struct writeback_control *wbc);
Scrive pagine dirty della cache su disco.

int balance_dirty_pages(struct bdi_writeback *wb, unsigned long pages);
Controlla e bilancia il numero di pagine dirty.

🔄 Read-ahead

void page_cache_sync_readahead(struct address_space *mapping, struct file_ra_state *ra, struct file *file, pgoff_t offset, unsigned long req_size);
Implementa read-ahead sincrono per accessi sequenziali.

void page_cache_async_readahead(struct address_space *mapping, struct file_ra_state *ra, struct file *file, struct page *page, pgoff_t offset, unsigned long req_size);
Implementa read-ahead asincrono per prestazioni ottimali.

void do_page_cache_readahead(struct address_space *mapping, struct file *file, pgoff_t offset, unsigned long nr_to_read);
Funzione principale per il read-ahead della page cache.

🔍 Esempi di Utilizzo Quotidiano

Quando un programma legge un file:

  1. find_get_page() - Cerca pagina nella cache
  2. page_cache_read() - Se trovata, restituisce dati da RAM
  3. page_cache_alloc() - Se non trovata, alloca nuova pagina
  4. add_to_page_cache() - Aggiunge pagina caricata alla cache
  5. Accesso successivo sarà cache hit

La page cache rende trasparenti le differenze tra RAM e storage!

🎬 Demo Interattiva: Come Funziona la Page Cache

💻 Simulazione: Lettura di un file con page cache

📄 File su Disco
/var/log/syslog (10MB)
(device: /dev/sda1, offset: 0x100000)
🗂️
🧠 Page Cache
Pagine 0x1000-0x2000
(2560 pagine da 4KB in RAM)
Comando eseguito: head -100 /var/log/syslog

🔄 Cosa succede dietro le quinte:

  1. 1. Cache lookup: Kernel cerca pagine 0-3 nell'address_space del file
  2. 2. Page fault: Prime pagine non in cache → genera page fault
  3. 3. I/O request: Block layer carica pagine dal disco (4KB * 4 = 16KB)
  4. 4. Cache population: Pagine aggiunte alla cache con radix_tree
  5. 5. Read-ahead: Carica automaticamente pagine successive (predictive)
  6. 6. Instant access: Letture successive sono cache hit da RAM
🎯 Risultato: Dopo il primo accesso, il file sembra "istantaneo"! La page cache trasforma I/O lento in accessi RAM veloci!

🎯 Concetti Chiave da Ricordare

🗂️

Address Space

Ogni file ha un address_space che collega offset logici a pagine fisiche in cache. È il "mappatore" tra file e memoria.

⚡

Cache Hit/Miss

Cache hit: dati in RAM, accesso istantaneo. Cache miss: page fault, caricamento da disco. Il rapporto hit/miss determina le prestazioni.

🔄

Write-Back Policy

Pagine dirty vengono scritte su disco in background. Bilancia prestazioni (scritture differite) con sicurezza dati (sincronizzazione).

🎯

Read-Ahead

Precaricamento intelligente di pagine anticipate. Pattern sequenziali, casuali, o predetti migliorano drasticamente le prestazioni.
