ACCESS FILES

Accesso ai file e gestione permessi

📁 ACCESSO FILE

DESCRIZIONE:

Access Files è il meccanismo del kernel Linux che gestisce i controlli di accesso ai file e alle risorse del sistema. Implementa le politiche di sicurezza basate sui permessi tradizionali (lettura, scrittura, esecuzione) e sui controlli degli accessi discrezionali (DAC), determinando se un processo può accedere a un file specifico in base all'UID, GID e ai permessi configurati.

CONFRONTO:

Immagina Access Files come un buttafuori di un nightclub: controlla l'identità di chi vuole entrare (processo), verifica se ha il biglietto giusto (permessi), e decide se permettere l'accesso alla festa (file). Se non hai il permesso giusto, non entri!

🔍 Descrizione Tecnica

Il sistema di controllo accessi implementa l'algoritmo di verifica dei permessi definito dallo standard POSIX, valutando i bit di permesso del file confrontandoli con l'identità del processo richiedente. Supporta i tre tipi di permesso fondamentali (rwx) per proprietario, gruppo e altri.

• Permessi Tradizionali - Controllo rwx per user/group/other

• Controllo DAC - Discretionary Access Control basato su identità

• Verifica Sequenziale - Controllo proprietario → gruppo → altri

• Interfaccia principale con il Virtual File System per ogni accesso ai file

⚙️ Operazioni Principali

Il controllo accessi gestisce diverse categorie di verifiche di sicurezza:

⚙️ Verifica Permessi

• generic_permission() - Controllo permessi generico per inode

• acl_permission_check() - Verifica ACL (Access Control Lists)

⚙️ Controllo Sicurezza

• security_inode_permission() - Hook LSM per controlli aggiuntivi

• capable() - Verifica capability del processo

⚙️ Gestione Identità

• current_uid() - Ottiene UID del processo corrente

• in_group_p() - Verifica appartenenza a gruppo

📋 Esempi Pratici

Il controllo accessi è attivo in ogni operazione sui file del sistema:

🔍 Lettura di un File

1. Processo chiama open() o read()

2. Kernel verifica permessi r del file

3. Se permesso negato, restituisce EACCES

4. Se permesso concesso, operazione prosegue

📄 Strutture Dati Chiave

  • struct cred - Credenziali del processo (UID, GID, capabilities)
  • struct inode - Metadati file con i_mode (permessi)
  • struct acl - Access Control List per permessi estesi
  • struct security_operations - Hook LSM per sicurezza avanzata

💻 Comandi Linux Essenziali

  • $ ls -l - Mostra permessi file in formato rwx
  • $ chmod 644 file - Cambia permessi file
  • $ chown user:group file - Cambia proprietario/gruppo
  • $ id - Mostra UID/GID del processo corrente

🎯 Caso Reale: Accesso Negato

Quando fai $ cat /etc/shadow come utente normale:

  1. Kernel verifica permessi del file (600 - rw-------)
  2. UID processo ≠ UID file (0) e non in gruppo root
  3. Controllo "others" permessi = no read
  4. Kernel restituisce "Permission denied"

💾 Supporto e Compatibilità

  • POSIX Permissions - Standard Unix permissions (rwx)
  • ACL Extensions - Access Control Lists (ext4, btrfs)
  • LSM Framework - Linux Security Modules (SELinux, AppArmor)
  • Capabilities - Permessi granulari per processi privilegiati
  • POSIX ACL - Liste di controllo accessi estese

✨ Caratteristiche Avanzate

  • SetUID/SetGID - Esecuzione con privilegi del proprietario
  • Sticky Bit - Solo proprietario può cancellare file
  • Immutable Flag - File non modificabile (chattr +i)
  • Extended Attributes - Metadati aggiuntivi per sicurezza

🔗 Interazioni Chiave

Il controllo accessi è integrato in tutto il sistema operativo:

💾 Virtual File System

• VFS Layer - Ogni chiamata system chiama controllo permessi

• Inode Operations - Hook permission() per controlli specifici

🌐 System Calls

• open()/read()/write() - Verificano permessi ad ogni accesso

• execve() - Controlla permessi esecuzione e setuid

🧠 Linux Security Modules

• SELinux/AppArmor - Politiche di sicurezza aggiuntive

• Capabilities - Permessi granulari oltre root/non-root

🛠️ API di Sicurezza

Queste sono le funzioni principali per gestire i controlli di accesso:

📂 Verifica Permessi

int access(const char *pathname, int mode);
Verifica se il processo può accedere al file con i permessi specificati (F_OK, R_OK, W_OK, X_OK).

int faccessat(int dirfd, const char *pathname, int mode, int flags);
Versione avanzata di access() che lavora relativo a un file descriptor di directory.

int euidaccess(const char *pathname, int mode);
Verifica accessi usando l'EUID effettivo invece dell'RUID reale.

int eaccess(const char *pathname, int mode);
Alias per euidaccess(), verifica permessi con EUID/EGID.

📊 Gestione Permessi

int chmod(const char *pathname, mode_t mode);
Cambia i permessi di un file (solo proprietario o root).

int chown(const char *pathname, uid_t owner, gid_t group);
Cambia proprietario e gruppo di un file (solo root).

int umask(mode_t mask);
Imposta la maschera di creazione file per i nuovi file.

💽 Controlli di Sicurezza

uid_t getuid(void);
Restituisce l'UID reale del processo corrente.

uid_t geteuid(void);
Restituisce l'UID effettivo (considera setuid).

🔍 Esempi di Utilizzo Pratico

Come utilizzare i controlli di accesso nella programmazione:

  1. if (access("file.txt", R_OK) == 0) - Verifica se puoi leggere il file
  2. umask(022) - Imposta permessi predefiniti per nuovi file (755)
  3. chmod("script.sh", 0755) - Rende eseguibile uno script
  4. chown("file", 1000, 1000) - Cambia proprietario (richiede root)

Queste API permettono di verificare e modificare i permessi dei file in modo sicuro e controllato.

🎬 Funzionamento del Controllo Accessi

💻 Come funziona la verifica dei permessi

📥 Richiesta Accesso
open("file.txt", O_RDONLY)
⚡
⚙️ Verifica Permessi
UID processo vs i_uid file
Processo eseguito: Il kernel confronta l'identità del processo richiedente con i permessi memorizzati nell'inode del file, applicando la logica proprietario→gruppo→altri secondo lo standard POSIX.

🔄 Algoritmo di Controllo Accessi:

  1. 1. Identificazione - Ottiene UID/EUID e GID/EGID del processo
  2. 2. Confronto Proprietario - Se UID processo = UID file, usa permessi owner
  3. 3. Confronto Gruppo - Se GID processo ∈ gruppi file, usa permessi group
  4. 4. Permessi Altri - Altrimenti usa permessi world (rwx per tutti)
🎯 Risultato: Accesso consentito se il bit di permesso corrispondente è impostato, altrimenti restituito EACCES (Permission denied) al processo richiedente.

🧪 Utilizzo Pratico dei Controlli Accessi

🔬 Esperimenti da fare sul tuo Linux

🔐 Verifica permessi file

$ ls -l /etc/passwd
-rw-r--r-- 1 root root 2455 gen 15 12:34 /etc/passwd

$ ls -l /etc/shadow
-rw-r----- 1 root shadow 1234 gen 15 12:34 /etc/shadow

Vedi i permessi in formato rwx per ogni file

👤 Controlla identità

$ id
uid=1000(user) gid=1000(user) groups=1000(user),27(sudo)

$ whoami
user

Scopri UID, GID e gruppi del tuo utente

⚙️ Cambia permessi

$ touch testfile
$ ls -l testfile
-rw-r--r-- 1 user user 0 gen 15 12:34 testfile

$ chmod 600 testfile
$ ls -l testfile
-rw------- 1 user user 0 gen 15 12:34 testfile

Cambia permessi per rendere file privato

🚫 Test accesso negato

$ cat /etc/shadow
cat: /etc/shadow: Permission denied

$ sudo cat /etc/shadow
[contenuto visibile come root]

Vedi come i permessi proteggono file sensibili

🎯 Concetti Chiave dei Controlli Accessi

🔐

DAC (Discretionary Access Control)

Controllo accessi discrezionali dove proprietari possono modificare permessi dei propri file secondo regole POSIX.

🛡️

LSM (Linux Security Modules)

Framework che permette di caricare moduli di sicurezza avanzati come SELinux e AppArmor per controlli granulari.

⚡

SetUID/SetGID

Bit speciali che permettono esecuzione programmi con privilegi del proprietario, abilitando sudo e comandi amministrativi.

📋

ACL (Access Control Lists)

Liste di controllo accessi estese che permettono permessi specifici per utenti e gruppi aggiuntivi oltre il modello tradizionale.
