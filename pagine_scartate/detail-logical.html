💾 FUNZIONI E IMPLEMENTAZIONI

DESCRIZIONE:

Le funzioni di implementazione del kernel sono il codice che esegue davvero ciò che le applicazioni richiedono tramite system call: il syscall dispatch instrada ogni richiesta dallo user space alla funzione giusta, mentre le VFS operations traducono le operazioni sui file in chiamate al filesystem specifico.

CONFRONTO:

Come il centralino di un'azienda: la chiamata arriva a un unico numero (syscall dispatch), il centralinista la smista all'interno giusto in base al numero composto, e l'ufficio competente (il filesystem, tramite le VFS ops) svolge il lavoro richiesto.

🔍 Descrizione Tecnica

Una system call è l'unico ingresso controllato dallo user space verso il kernel. Immagina un edificio con un'unica reception: ogni visitatore (applicazione) dichiara cosa vuole tramite un numero di servizio, la reception (dispatcher) consulta l'elenco e lo accompagna all'ufficio giusto, che a sua volta può delegare a specialisti diversi (ext4, XFS, procfs...).

• Syscall entry - Il punto di ingresso in assembly (entry_SYSCALL_64) salva i registri e passa al codice C

• Syscall dispatch - Il numero della syscall indicizza la sys_call_table per trovare la funzione da eseguire

• Implementazioni SYSCALL_DEFINE - Ogni syscall è una funzione C che valida gli argomenti e chiama il sottosistema

• VFS ops - Tabelle di puntatori a funzione (file_operations, inode_operations) che nascondono le differenze tra filesystem

• Polimorfismo in C - Lo stesso read() funziona su file, pipe, socket e dispositivi

• Ritorno allo user space - Risultato o errore (-errno) tornano al chiamante con sysret

• Interazione: Il dispatcher chiama la funzione della syscall, che a sua volta usa le VFS ops del filesystem su cui risiede il file

⚙️ Componenti di Dispatch e VFS

Syscall dispatch e VFS sono i due livelli attraverso cui una richiesta raggiunge l'implementazione concreta:

🏗️ Syscall Entry

• entry_SYSCALL_64 - Punto di ingresso dell'istruzione SYSCALL su x86-64

• Registri - Numero in RAX, argomenti in RDI, RSI, RDX, R10, R8, R9

• pt_regs - Struttura che salva lo stato dello user space

• Controlli preliminari - Seccomp, audit e tracing prima del dispatch

📦 Dispatch Table

• sys_call_table - Array di puntatori a funzione indicizzato dal numero di syscall

• do_syscall_64() - Funzione C che legge il numero e invoca l'handler

• syscall_64.tbl - File che associa numeri e nomi delle syscall

• Numero non valido - Il dispatcher restituisce -ENOSYS

💾 VFS Operations

• file_operations - read, write, open, mmap, ioctl, poll per ogni tipo di file

• inode_operations - lookup, create, mkdir, unlink sui nodi del filesystem

• super_operations - Gestione del superblock: alloc_inode, sync_fs, statfs

• dentry_operations - Comportamento della cache dei nomi (revalidate, hash)

📋 Esempi Pratici

Quando un programma chiama read() su un file, ecco cosa succede:

🔍 Percorso di una read()

1. La libc carica il numero 0 in RAX ed esegue l'istruzione SYSCALL

2. entry_SYSCALL_64 salva i registri e chiama do_syscall_64()

3. Il dispatcher usa sys_call_table per raggiungere ksys_read()

4. vfs_read() chiama il metodo read_iter delle file_operations del filesystem

5. I dati tornano in user space con copy_to_user() e sysret

📄 Strutture Dati Chiave

  • file - Istanza di file aperto con f_op, posizione e flag
  • inode - Metadati del file e puntatore a inode_operations
  • pt_regs - Registri salvati all'ingresso nel kernel
  • file_operations - Tabella di puntatori alle funzioni di I/O

💻 Nel Computer: Come Vederlo?

Comandi Linux per osservare syscall e VFS:

  • strace ls - Mostra le syscall eseguite da un programma
  • ausyscall --dump - Elenca numeri e nomi delle syscall
  • cat /proc/PID/syscall - Mostra la syscall in corso di un processo
  • cat /proc/filesystems - Elenca i filesystem registrati nel VFS
  • perf trace ls - Traccia le syscall con basso overhead

🎯 Caso Reale: Apertura di un file

Quando un'applicazione esegue open():

  1. do_sys_open() risolve il percorso con il path walk, usando lookup di inode_operations
  2. Il VFS trova o crea il dentry e l'inode del file
  3. Viene allocata una struct file con f_op copiato dall'inode
  4. Il VFS chiama il metodo open delle file_operations
  5. Il file descriptor viene installato nella tabella del processo e restituito

🔧 Famiglie di Syscall

  • File I/O - read, write, open, close, lseek
  • Processi - fork, execve, exit, wait4
  • Memoria - mmap, brk, munmap, mprotect
  • Directory - mkdir, rmdir, getdents64, rename
  • Socket e IPC - socket, pipe2, futex

✨ Caratteristiche

  • Uniformità - Un'unica interfaccia per file, pipe, socket e dispositivi
  • Estensibilità - Nuovi filesystem si registrano fornendo le proprie ops
  • Sicurezza - Argomenti validati, accessi controllati con LSM
  • Prestazioni - Ingresso rapido con SYSCALL e vDSO
  • Compatibilità - ABI stabile verso lo user space

🔗 Interazioni Chiave

Syscall dispatch e VFS ops interagiscono con molteplici componenti del sistema:

🛡️ Sicurezza e Tracing

• seccomp - Filtra le syscall consentite a un processo

• Audit - Registra le syscall rilevanti

• ptrace/strace - Intercetta le syscall per il debug

🗂️ Filesystem

• Registrazione - register_filesystem() associa il nome del filesystem alle sue operazioni

• Page cache - Le read_iter leggono dalla cache delle pagine

• Block layer - I filesystem inviano l'I/O al livello a blocchi

🔄 Processi e Memoria

• Tabella dei descriptor - files_struct associa fd e struct file

• copy_to_user/copy_from_user - Trasferimento sicuro dei dati

• Scheduler - Una syscall bloccante mette il task a dormire

🛠️ API e Funzioni Principali

Queste sono le funzioni principali di syscall dispatch e VFS:

🏗️ Syscall Dispatch

SYSCALL_DEFINE3(read, unsigned int, fd, char __user *, buf, size_t, count)
Macro che definisce l'implementazione della syscall read.

void do_syscall_64(struct pt_regs *regs, int nr);
Legge il numero e invoca la funzione in sys_call_table.

ssize_t ksys_read(unsigned int fd, char __user *buf, size_t count);
Implementazione interna di read, riutilizzabile dal kernel.

📦 VFS: Lettura e Scrittura

ssize_t vfs_read(struct file *file, char __user *buf, size_t count, loff_t *pos);
Controlla i permessi e chiama il metodo read del file.

ssize_t vfs_write(struct file *file, const char __user *buf, size_t count, loff_t *pos);
Controlla i permessi e chiama il metodo write del file.

int vfs_fsync(struct file *file, int datasync);
Forza la scrittura su disco dei dati del file.

💾 VFS: File e Filesystem

int vfs_open(const struct path *path, struct file *file);
Apre il file e invoca il metodo open delle file_operations.

int vfs_getattr(const struct path *path, struct kstat *stat, u32 request_mask, unsigned int query_flags);
Ottiene gli attributi del file (usata da stat).

int register_filesystem(struct file_system_type *fs);
Registra un nuovo filesystem nel VFS.

🔍 Esempi di Utilizzo Quotidiano

Quando osservi cosa fa un programma:

  1. strace -e trace=openat,read cat /etc/hostname - Segui open e read
  2. strace -c ls /usr - Riepiloga le syscall per tipo
  3. ls -l /proc/self/fd - Vedi i file descriptor aperti
  4. cat /proc/mounts - Vedi i filesystem montati
  5. Ogni richiesta attraversa dispatch e VFS prima di arrivare al disco

Tutto questo avviene a ogni accesso a un file, migliaia di volte al secondo!

🎬 Demo Interattiva: Percorso di una read()

💻 Simulazione: read() su un file ext4

📥 Chiamata Utente
read(3, buf, 4096)
(syscall n. 0 su x86-64)
⚡
🔍 Funzione Eseguita
ksys_read → vfs_read
(ext4_file_read_iter)
Percorso eseguito: SYSCALL → do_syscall_64() → sys_call_table[0] → ksys_read()

🔄 Cosa succede dietro le quinte:

  1. 1. Ingresso: SYSCALL passa al kernel e entry_SYSCALL_64 salva i registri in pt_regs
  2. 2. Dispatch: do_syscall_64 usa il numero in RAX per indicizzare sys_call_table
  3. 3. Implementazione: ksys_read risolve il descriptor 3 nella struct file
  4. 4. VFS ops: vfs_read invoca f_op->read_iter, qui implementato da ext4
  5. 5. Ritorno: copy_to_user trasferisce i dati e sysret torna in user space con i byte letti
🎯 Risultato: Lo stesso read() funzionerebbe identico su pipe, socket o dispositivi: cambia solo la tabella di ops puntata da f_op, non il codice del chiamante!

🎯 Concetti Chiave da Ricordare

🚪

Un Solo Ingresso

Ogni richiesta dello user space passa da un unico punto di ingresso controllato. Il numero della syscall sceglie la funzione da eseguire e gli argomenti vengono validati prima dell'uso.

📋

Tabelle di Puntatori

La sys_call_table indirizza alla syscall giusta, le VFS ops indirizzano al filesystem giusto. È polimorfismo in C: stessa chiamata, implementazioni diverse.

🏗️

VFS Uniforme

Il VFS offre la stessa interfaccia per ogni filesystem. ext4, XFS, procfs e le pipe implementano le stesse ops, quindi il codice utente non cambia.

🛡️

Costo e Sicurezza

Passare al kernel ha un costo, quindi si riducono le chiamate (vDSO, buffering). Ogni accesso è controllato da permessi, seccomp e LSM.
