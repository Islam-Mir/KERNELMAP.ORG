🌐 MEMORIA VIRTUALE

DESCRIZIONE:

Il sistema di memoria virtuale del kernel Linux permette a ogni processo di avere il proprio spazio di indirizzamento privato, isolato dagli altri processi. Ogni programma "vede" di avere tutta la memoria del sistema per sé, ma il kernel gestisce intelligentemente la condivisione delle risorse fisiche.

CONFRONTO:

Come un condominio dove ogni appartamento ha il suo indirizzo privato (0x00000000-0xFFFFFFFF), ma condividono lo stesso edificio. Il portiere (kernel) gestisce chi può accedere a cosa e quando.

🔍 Descrizione Tecnica

La memoria virtuale è il cuore della gestione memoria in Linux, fornendo isolamento, protezione e condivisione efficiente delle risorse. Immagina di avere un ristorante dove ogni cliente ha il suo menu privato, ma la cucina condivisa prepara tutti i piatti. L'MMU (Memory Management Unit) è il maître che traduce richieste in realtà fisica.

• Traduzione indirizzi - MMU converte indirizzi virtuali in indirizzi fisici attraverso page table

• Isolamento processi - Ogni processo ha il proprio spazio di indirizzamento (4GB su 32-bit, 256TB su 64-bit)

• Paging su richiesta - Caricamento lazy delle pagine dalla memoria al disco

• Condivisione intelligente - Codice eseguibile e librerie condivise tra processi

• Protezione memoria - Controllo rigoroso degli accessi (lettura/scrittura/esecuzione)

• Overcommit - Allocazione di più memoria virtuale di quella fisica disponibile

• Interazione: Coordina con l'MMU hardware, il page cache, e il swap subsystem

⚙️ Meccanismi di Memoria Virtuale

Il kernel Linux implementa diversi livelli di gestione memoria virtuale:

🔄 Page Table Management

• Multi-level page tables - Gerarchia a 4 livelli (PML4/PDP/PD/PT) per efficienza

• TLB (Translation Lookaside Buffer) - Cache hardware per traduzioni rapide

• Huge pages - Pagine da 2MB/1GB per ridurre overhead di traduzione

• Page table isolation - Separazione kernel/user per sicurezza

💾 Demand Paging

• Page fault handling - Caricamento on-demand di pagine dalla memoria di massa

• Copy-on-write - Condivisione efficiente di pagine fino alla modifica

• Memory-mapped files - Trattamento di file come memoria estesa

• Anonymous pages - Pagine di memoria senza file backing

🔄 Swapping e Page Replacement

• LRU approximation - Algoritmi per scegliere quali pagine rimpiazzare

• Swap space - Partizione/disco per estendere la RAM virtualmente

• Page clustering - Scambio di multiple pagine insieme per efficienza

• Dirty page tracking - Scrittura selettiva solo delle pagine modificate

📋 Esempi Pratici

La memoria virtuale permea ogni aspetto dell'uso quotidiano di Linux:

🔍 Page Fault: Caricamento Pigro

Quando lanci un programma di 100MB:

  1. Mappatura iniziale - Kernel mappa tutto lo spazio virtuale (100MB) ma non carica nulla
  2. Primo accesso - Programma accede alla prima istruzione → page fault
  3. Caricamento on-demand - Kernel carica solo la pagina necessaria dal disco
  4. Esecuzione continua - Programma funziona normalmente, altre pagine caricate al bisogno

⚡ Copy-on-Write: Fork Efficace

  • Processo padre - Ha 200MB di memoria mappata
  • fork() chiamato - Figlio creato istantaneamente (nessuna copia fisica)
  • Condivisione iniziale - Entrambi processi condividono le stesse pagine fisiche
  • Modifica primo - Quando uno modifica una pagina → copy-on-write attiva
  • Separazione fisica - Solo allora viene creata una copia fisica della pagina

🗂️ Memory-Mapped Files

  • mmap() - Mappa un file nello spazio di indirizzamento virtuale
  • Accesso diretto - Leggi/scrivi come se fosse memoria normale
  • Paging automatico - Kernel gestisce caricamento/scaricamento
  • Condivisione IPC - File mappati visibili tra processi
  • Database efficienti - MySQL/PostgreSQL usano mmap per performance

💻 Nel Computer: Come Osservarla?

Comandi Linux per esplorare la memoria virtuale:

  • ps aux - Mostra uso memoria virtuale (VSZ) vs fisica (RSS)
  • pmap PID - Mappa completa dello spazio virtuale di un processo
  • cat /proc/PID/maps - Dettagli di ogni regione di memoria
  • vmstat - Statistiche di swapping e page fault
  • free -h - Memoria totale vs disponibile
  • swapon -s - Spazi di swap attivi

🎯 Caso Reale: Browser Web

Un browser con 20 tab aperte:

  1. Isolamento processi - Ogni tab ha il suo spazio virtuale isolato
  2. Condivisione librerie - libc, libgtk condivise tra processi
  3. Memory overcommit - Totale memoria virtuale > RAM fisica
  4. Swapping intelligente - Pagine meno usate vanno su disco
  5. Crash isolation - Un tab che crasha non uccide gli altri

💾 Architetture Supportate

  • x86 paging - Page table a 2/3/4 livelli con PAE
  • x86-64 paging - 4 livelli, 48-bit indirizzi virtuali
  • ARM paging - Supporto LPAE per indirizzi estesi
  • RISC-V paging - Sv39/Sv48 per indirizzi virtuali

✨ Caratteristiche

  • Isolamento completo - Processi non possono accedere memoria altrui
  • Overcommit configurabile - Allocazione oltre i limiti fisici
  • Protezione granulare - Controllo read/write/execute per pagina
  • Condivisione efficiente - Codice e dati condivisi tra processi
  • Swapping trasparente - Estensione RAM attraverso disco

🔗 Interazioni Chiave

La memoria virtuale è il collante che tiene insieme tutto il sistema di gestione memoria:

🧠 Memory Manager

• Page allocator - Gestisce allocazione pagine fisiche

• Slab allocator - Cache oggetti per strutture kernel

• Buddy system - Allocazione contigua per dispositivi

💾 Virtual File System

• Memory-mapped I/O - File trattati come memoria estesa

• Page cache - Cache intelligente per file system

• Buffer cache - Cache per metadata filesystem

⚙️ Process Scheduler

• Context switching - Cambio rapido tra spazi virtuali

• Memory limits - Controllo risorse per processo (ulimit)

• Out-of-memory killer - Terminazione processi per salvare sistema

🔐 Security Framework

• ASLR - Randomizzazione indirizzi per sicurezza

• NX bit - Protezione esecuzione codice da dati

• SMAP/SMEP - Protezione supervisor mode

💽 Storage Subsystems

• Swap device - Estensione memoria attraverso storage

• Compressed swap - Compressione pagine swap (zswap)

• Huge pages - Pagine grandi per applicazioni ad alte prestazioni

🛠️ API Principali

Queste sono le funzioni che ogni programmatore usa per gestire la memoria virtuale:

📋 Gestione Memoria Virtuale

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
Mappa file o memoria anonima nello spazio virtuale del processo.

int munmap(void *addr, size_t length);
Rimuove un mapping di memoria virtuale.

void *mremap(void *old_address, size_t old_size, size_t new_size, int flags);
Ridimensiona o sposta un'area di memoria mappata.

🔒 Controllo Protezione Memoria

int mprotect(void *addr, size_t len, int prot);
Cambia i permessi di protezione di un'area di memoria.

int madvise(void *addr, size_t length, int advice);
Fornisce suggerimenti al kernel su come gestire la memoria (MADV_RANDOM, MADV_SEQUENTIAL).

🎯 Esempi di Utilizzo Quotidiano

Quando un programma alloca memoria dinamica:

  1. malloc(1024) - Richiesta 1KB di memoria
  2. brk()/mmap() - Kernel estende heap o mappa memoria anonima
  3. Page fault - Primo accesso causa caricamento pagina fisica
  4. Zero-fill - Memoria inizializzata a zero per sicurezza
  5. Ritorno puntatore - Programma riceve indirizzo virtuale valido

Ogni allocazione coinvolge la memoria virtuale, anche se il programmatore non lo sa!

💻 Simulazione di un Page Fault

📄 Pagina Virtuale
Indirizzo: 0x400000
(non presente in RAM)
⚠️
🚨 Page Fault
Interrupt CPU
(kernel gestisce)
Comando che causa page fault: ./programma_grande

🔄 Sequenza del page fault:

  1. 1. Accesso memoria - Programma accede a indirizzo virtuale 0x400000
  2. 2. Controllo MMU - Page table indica pagina non presente in RAM
  3. 3. Interrupt CPU - Eccezione page fault generata automaticamente
  4. 4. Kernel handler - do_page_fault() determina tipo di fault
  5. 5. Allocazione fisica - Kernel trova o alloca pagina RAM libera
  6. 6. Caricamento dati - Dati copiati da swap/disco alla RAM
  7. 7. Aggiornamento PT - Page table aggiornata con nuovo mapping
  8. 8. Ripresa esecuzione - Programma continua come se nulla fosse successo!
🎯 Risultato: Il programma non si accorge di nulla! La memoria virtuale rende trasparente la complessità della gestione fisica della memoria. Questo è il potere dell'astrazione!

🧪 Laboratorio Pratico: Esplora la Memoria Virtuale

🔬 Esperimenti da fare sul tuo Linux

📊 Analizza spazio virtuale

$ pmap $$ | head -10
$ cat /proc/$$/maps | head -5
$ ps aux --sort -vsz | head
$ free -h

Esamina come ogni processo usa lo spazio virtuale

⚠️ Genera page fault

$ vmstat 1
$ dd if=/dev/zero of=/tmp/test bs=1M count=100
$ cat /tmp/test > /dev/null
$ rm /tmp/test

Osserva page fault durante accesso a file grandi

🔄 Test copy-on-write

$ ps aux | grep bash
$ strace -f -e trace=memory bash -c 'echo test'
$ pmap [PID] | grep total

Vedi come fork() usa copy-on-write per efficienza

💾 Esplora swapping

$ swapon -s
$ vmstat -s | grep swap
$ stress --vm 1 --vm-bytes 1G --timeout 10s
$ free -h

Testa il sistema di swapping sotto stress

🎯 Concetti Chiave da Ricordare

🔒

Isolamento Completo

Ogni processo vive nel suo mondo virtuale. Un crash di memoria in un programma non può danneggiare gli altri processi o il kernel stesso.

⚡

Caricamento Pigro

I programmi si avviano velocemente perché il kernel carica le pagine di memoria solo quando realmente necessarie, non tutto in una volta.

🔄

Condivisione Intelligente

Codice eseguibile e librerie sono condivisi tra processi fino alla modifica, risparmiando memoria e migliorando le performance.

💾

Estensione Trasparente

Il disco diventa "RAM estesa" attraverso lo swapping. I programmi continuano a funzionare anche quando la memoria fisica è piena.
