Virtual Memory

Gestione della memoria virtuale

🧠 GESTIONE MEMORIA VIRTUALE

DESCRIZIONE:

La Virtual Memory è un meccanismo fondamentale del kernel Linux che permette ai processi di utilizzare uno spazio di indirizzamento virtuale molto più grande della memoria fisica disponibile. Ogni processo vede uno spazio di indirizzamento privato e contiguo, mentre il kernel gestisce la mappatura tra indirizzi virtuali e fisici attraverso le page tables.

CONFRONTO:

Immagina la Virtual Memory come un sistema di archiviazione intelligente: ogni processo ha il proprio "magazzino virtuale" (spazio di indirizzamento) che sembra infinito, ma il kernel è il magazziniere che gestisce lo spazio fisico reale, spostando "scatole" (pagine) tra scaffali (RAM) e deposito esterno (swap) secondo necessità.

🔍 Descrizione Tecnica

La Virtual Memory nel kernel Linux gestisce la traduzione da indirizzi virtuali a fisici, l'isolamento tra processi, il demand paging, il copy-on-write e lo swapping. Fornisce astrazione, protezione e condivisione efficiente della memoria fisica.

• Address Translation - Traduzione indirizzi virtuali → fisici via page tables

• Memory Isolation - Ogni processo ha spazio indirizzamento privato

• Demand Paging - Caricamento pagine solo quando necessario

• Copy-on-Write - Condivisione efficiente memoria fork

• Memory Mapping - Mappatura file e dispositivi in memoria

• Interfaccia principale tra processi e memoria fisica del sistema

⚙️ Componenti della Virtual Memory

La Virtual Memory nel kernel Linux è composta da diversi livelli:

🔧 Page Tables

• Multi-level tables - Tabelle gerarchiche per efficienza

• PTE entries - Page Table Entries con flags e indirizzi

• Huge pages - Pagine grandi per prestazioni

• Page attributes - Cacheability, global, dirty bits

🚀 Translation Lookaside Buffer (TLB)

• Address cache - Cache traduzioni recenti

• TLB miss handling - Gestione mancati nella cache

• TLB shootdown - Invalida entries in SMP

• ASID support - Address Space ID per isolamento

📋 Virtual Memory Areas (VMA)

• vm_area_struct - Descrittore regioni memoria

• Red-black tree - Organizzazione efficiente VMA

• Permission flags - Read, write, execute rights

• File mapping - Collegamento a file su disco

📋 Esempi Pratici

La Virtual Memory è coinvolta in ogni accesso alla memoria da parte dei processi, dalla semplice lettura di variabili alla gestione complessa del memory mapping:

🔍 Page Fault Flow

1. Processo accede a indirizzo virtuale non mappato

2. CPU genera page fault exception

3. Kernel verifica validità indirizzo (VMA)

4. Kernel alloca pagina fisica e aggiorna page table

5. Processo riprende esecuzione

📄 Strutture Dati Chiave

  • struct mm_struct - Descrittore spazio indirizzamento processo
  • struct vm_area_struct - Regione contigua memoria virtuale (VMA)
  • pgd_t, pud_t, pmd_t, pte_t - Livelli page tables
  • struct page - Descrittore pagina fisica

💻 Nel Computer: Come Vederlo?

Comandi Linux per esplorare la virtual memory:

  • cat /proc/pid/maps - Mappature memoria di un processo
  • pmap pid - Dettagli uso memoria processo
  • cat /proc/meminfo - Statistiche memoria sistema
  • vmstat - Statistiche virtual memory
  • cat /proc/sys/vm/swappiness - Configurazione swap

🎯 Caso Reale: Memory Mapping File

Quando un processo fa mmap() di un file:

  1. Kernel crea nuova VMA nello spazio processo
  2. VMA collegata al file tramite vm_file
  3. Nessuna pagina fisica allocata inizialmente
  4. Primo accesso genera page fault
  5. Kernel legge dati da file e mappa in memoria
  6. Accessi successivi sono diretti (no I/O)

🔧 Meccanismi della Virtual Memory

  • Demand paging - Caricamento pagine su richiesta
  • Copy-on-write - Condivisione efficiente fork
  • Memory-mapped files - File come memoria
  • Shared memory - Memoria condivisa processi
  • Swapping - Spostamento pagine su disco
  • Huge pages - Pagine grandi per prestazioni

✨ Caratteristiche

  • Isolamento - Ogni processo spazio privato
  • Astrazione - Memoria virtuale vs fisica
  • Efficienza - Demand paging e caching
  • Flessibilità - Mapping dinamico
  • Scalabilità - Supporto memoria grande
  • Protezione - Controllo accessi

🛠️ API e System Calls

Queste sono le interfacce principali per la virtual memory:

📂 Memory Mapping

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
Mappa file o dispositivo in memoria virtuale.

int munmap(void *addr, size_t length);
Rimuove mapping memoria creato con mmap.

int mprotect(void *addr, size_t len, int prot);
Cambia protezione di area memoria.

🔄 Memory Management

void *malloc(size_t size);
Alloca memoria heap (userspace).

void *kmalloc(size_t size, gfp_t flags);
Alloca memoria kernel.

void kfree(void *ptr);
Libera memoria allocata con kmalloc.

🎯 Virtual Memory Operations

int madvise(void *addr, size_t length, int advice);
Fornisce consigli al kernel su uso memoria.

int mlock(const void *addr, size_t len);
Blocca pagine in memoria fisica.

int munlock(const void *addr, size_t len);
Sblocca pagine precedentemente bloccate.

🔍 Esempi di Utilizzo Quotidiano

Quando lanci un programma:

  1. execve() carica eseguibile e setup spazio virtuale
  2. Page fault per caricamento codice e dati
  3. mmap() per librerie condivise
  4. malloc() per heap dinamico
  5. Copy-on-write per condivisione memoria fork
  6. Swap per gestire pressione memoria

Tutta questa complessità è trasparente grazie alla virtual memory!

🎬 Demo Interattiva: Virtual Memory Translation

💻 Simulazione: Traduzione Indirizzo Virtuale

📝 Processo
char *ptr = mmap(...);
ptr[0] = 'A';
(Virtual: 0x7f8d4c000000)
⚡
🧠 Virtual Memory
Virtual → Physical
(Physical: 0x12345678000)
Sequenza traduzione: Virtual 0x7f8d4c000000 → VMA lookup → Page table walk → Physical 0x12345678000

🔄 Cosa succede nei nanosecondi:

  1. 1. Memory access: Istruzione accede indirizzo virtuale
  2. 2. VMA check: Kernel verifica regione valida
  3. 3. TLB lookup: Controlla cache traduzioni (hit ~1ns)
  4. 4. Page walk: Se miss, attraversa 4 livelli page table (~100ns)
  5. 5. Permission check: Verifica diritti lettura/scrittura
  6. 6. Physical access: CPU accede indirizzo fisico in RAM
  7. 7. Data return: Valore restituito al processo
🎯 Risultato: Il processo lavora con indirizzi virtuali come se fossero diretti, ma il sistema ha tradotto, protetto e ottimizzato l'accesso. Tutto trasparente grazie alla virtual memory!

$ cat /proc/self/maps

📊 Analizza uso memoria virtuale

$ ps -o pid,ppid,cmd,vsz,rss -C bash

1234 1 bash 12345 2345
$ pmap 1234 | head -20

Confronta VSZ (virtual) vs RSS (resident) memory

⚡ Monitora page faults

$ ps -o pid,ppid,cmd,min_flt,maj_flt -C bash

1234 1 bash 150 2
$ vmstat 1
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----

Osserva page faults e attività swap

🔍 Testa huge pages

$ cat /proc/meminfo | grep -i huge
HugePages_Total: 0
HugePages_Free: 0
HugePages_Rsvd: 0
$ echo 1 > /proc/sys/vm/nr_hugepages

Abilita e monitora huge pages per prestazioni

🎯 Concetti Chiave da Ricordare

📋

Page Tables

Strutture dati gerarchiche che mappano indirizzi virtuali a fisici. Su x86-64 sono 4 livelli per supportare spazi di indirizzamento vasti ed efficienti.

⚡

Demand Paging

Le pagine vengono caricate in memoria solo quando accedute, permettendo esecuzione programmi più grandi della RAM e avvio più veloce.

🛡️

Memory Protection

Ogni regione di memoria virtuale ha permessi specifici (R/W/X). Violazioni generano segfault, proteggendo processi da corruption.

🔄

Copy-on-Write

Ottimizzazione per fork(): memoria condivisa fino alla modifica. Risparmia RAM e velocizza creazione processi.
