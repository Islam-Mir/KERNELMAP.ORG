Protocolli di Comunicazione

📡 PROTOCOLLI

DESCRIZIONE:

I Protocolli gestiscono le regole e gli algoritmi di comunicazione tra dispositivi, implementando stack completi per trasmissione affidabile di dati attraverso reti.

CONFRONTO:

Come un sistema di posta elettronica digitale: ogni protocollo è una busta con regole precise (indirizzi, formato, consegna), che garantisce che i messaggi (pacchetti) arrivino a destinazione nel modo corretto e affidabile.

🔍 Descrizione Tecnica

I Protocolli sono l'implementazione delle specifiche di comunicazione di rete nel kernel Linux, gestendo handshake, controllo di flusso, correzione errori e segmentazione dei dati. Immagina un'orchestra di protocolli che lavorano in armonia: TCP garantisce consegna affidabile, UDP offre velocità, IP instrada pacchetti, mentre Ethernet li trasporta fisicamente attraverso il mezzo.

• TCP implementation - Protocollo orientato connessione con controllo flusso e ritrasmissione

• UDP implementation - Protocollo senza connessione per bassa latenza

• IP routing - Instradamento pacchetti attraverso reti complesse

• ICMP handling - Gestione messaggi di controllo e diagnostica

• ARP resolution - Risoluzione indirizzi IP in MAC address

• Fragmentation/reassembly - Gestione pacchetti troppo grandi per MTU

• Interazione: Coordina con socket layer per fornire API di rete affidabili

⚙️ Operazioni Principali

I Protocolli gestiscono quattro aspetti fondamentali della comunicazione di rete, ciascuno essenziale per trasmissione affidabile:

🔗 Connection Management

• tcp_connect() - Stabilisce connessione TCP con three-way handshake

• tcp_accept() - Accetta connessioni in entrata

• tcp_close() - Chiude connessione con four-way handshake

• tcp_abort() - Termina connessione forzatamente

• tcp_listen() - Mette socket in ascolto per connessioni

📦 Data Transmission

• tcp_sendmsg() - Invia dati con controllo flusso e ritrasmissione

• tcp_recvmsg() - Riceve dati con riassemblaggio e ordinamento

• udp_sendmsg() - Invia datagram UDP senza garanzia consegna

• udp_recvmsg() - Riceve datagram UDP

• ip_forward() - Inoltra pacchetti IP tra interfacce

🛡️ Error Control

• tcp_retransmit() - Ritrasmette pacchetti persi

• tcp_ack() - Invia acknowledgment di ricezione

• tcp_reset() - Invia segmento RST per errori

• icmp_send() - Invia messaggi ICMP (ping, errori)

• tcp_keepalive() - Mantiene connessioni attive

⚡ Performance Optimization

• tcp_congestion_control() - Gestisce controllo congestione TCP

• tcp_window_update() - Aggiorna finestra di ricezione

• tcp_fast_retransmit() - Ritrasmissione veloce su duplicate ACK

• tcp_slow_start() - Algoritmo slow start per evitare congestione

• tcp_nagle() - Algoritmo Nagle per ridurre piccoli pacchetti

📋 Esempi Pratici

Quando navighi su un sito web, ecco cosa succede nei protocolli di rete:

🔍 Three-Way Handshake TCP

1. Il browser invia SYN per stabilire connessione TCP

2. Il server risponde con SYN-ACK confermando ricezione

3. Il browser invia ACK completando l'handshake

4. La connessione TCP è ora stabilita e affidabile

📄 Strutture Dati Chiave

  • struct sock - Rappresenta un socket con indirizzi, porte, stati connessione
  • struct tcp_sock - Estende sock con sequence numbers, window sizes, timers TCP
  • struct sk_buff - Buffer per pacchetti di rete con headers e payload
  • struct net_device - Descrive interfaccia di rete con indirizzo MAC e MTU

💻 Nel Computer: Come Vederlo?

Comandi Linux per esplorare i protocolli:

  • ss -tuln - Mostra socket TCP/UDP in ascolto
  • netstat -antp - Visualizza connessioni TCP attive
  • tcpdump -i eth0 tcp port 80 - Cattura pacchetti TCP sulla porta 80
  • ping google.com - Test ICMP connectivity

🎯 Caso Reale: Download File HTTP

Quando scarichi un file da un server web:

  1. DNS risolve nome dominio in indirizzo IP
  2. TCP stabilisce connessione affidabile (three-way handshake)
  3. HTTP invia richiesta GET per il file
  4. Server risponde con contenuto del file
  5. TCP garantisce consegna ordinata e ritrasmette se necessario
  6. Connessione viene chiusa con four-way handshake

📡 Protocolli Supportati

  • TCP (Transmission Control Protocol) - Consegna affidabile e ordinata
  • UDP (User Datagram Protocol) - Trasferimento veloce senza garanzia
  • IP (Internet Protocol) - Instradamento pacchetti attraverso reti
  • ICMP (Internet Control Message Protocol) - Messaggi di controllo e diagnostica
  • ARP (Address Resolution Protocol) - Risoluzione IP in indirizzi MAC

✨ Caratteristiche

  • Reliability - TCP garantisce consegna affidabile con ritrasmissione
  • Flow Control - Gestione congestione e controllo flusso adattivo
  • Error Detection - Checksum e correzione errori integrata
  • Connection Management - Handshake e teardown strutturato
  • Performance Optimization - Algoritmi slow-start, congestion avoidance

🔗 Interazioni Chiave

I protocolli sono il livello fondamentale dello stack di rete del kernel Linux:

🔌 Socket Layer

• System calls - socket(), bind(), connect(), send(), recv() interfacciano con protocolli

• Socket buffers - Gestione code di trasmissione e ricezione

🌐 Network Stack

• IP layer - Instradamento e forwarding pacchetti tra interfacce

• Netfilter - Firewalling e NAT attraverso hook nei protocolli

🧠 Memory Management

• SKB allocation - Gestione buffer per pacchetti di rete

• Page allocation - Memoria per strutture protocollo e code

⚙️ Device Drivers

• Network drivers - Interfaccia con hardware di rete (NIC)

• Interrupt handling - Gestione eventi hardware di rete

🔐 Security Framework

• Netfilter hooks - Filtri di sicurezza integrati nei protocolli

• TCP options - Estensioni sicurezza come TCP MD5

🛠️ API Principali

Queste sono le funzioni chiave per gestire i protocolli di rete nel kernel Linux:

🔌 Socket Operations

int sock_create(int family, int type, int protocol, struct socket **res);
Crea un nuovo socket per il protocollo specificato.

int inet_bind(struct socket *sock, struct sockaddr *uaddr, int addr_len);
Associa un indirizzo locale al socket.

int tcp_connect(struct sock *sk, struct sockaddr *uaddr, int addr_len);
Stabilisce connessione TCP con three-way handshake.

📦 Data Transmission

int tcp_sendmsg(struct sock *sk, struct msghdr *msg, size_t size);
Invia dati TCP con controllo flusso e ritrasmissione.

int tcp_recvmsg(struct sock *sk, struct msghdr *msg, size_t len, int flags);
Riceve dati TCP con riassemblaggio e ordinamento.

int udp_sendmsg(struct sock *sk, struct msghdr *msg, size_t len);
Invia datagram UDP senza garanzia consegna.

⚙️ Protocol Management

void tcp_retransmit_timer(struct sock *sk);
Gestisce ritrasmissione pacchetti TCP persi.

void tcp_congestion_control(struct sock *sk);
Applica algoritmi controllo congestione TCP.

int icmp_send(struct sk_buff *skb, int type, int code);
Invia messaggi ICMP per diagnostica e controllo.

🔍 Esempi di Utilizzo Quotidiano

Quando fai wget http://example.com/file.zip:

  1. sock_create(AF_INET, SOCK_STREAM, IPPROTO_TCP) - Crea socket TCP
  2. tcp_connect() - Three-way handshake con server
  3. tcp_sendmsg() - Invia richiesta HTTP
  4. tcp_recvmsg() - Riceve risposta con ritrasmissione automatica
  5. Connessione chiusa con four-way handshake

I protocolli rendono affidabile la comunicazione di rete nonostante perdite e ritardi!

🔄 Cosa succede dietro le quinte:

  1. 1. DNS Resolution: Risoluzione nome dominio in indirizzo IP
  2. 2. Three-way Handshake: SYN → SYN-ACK → ACK per stabilire connessione TCP
  3. 3. HTTP Request: Invio richiesta GET attraverso connessione affidabile
  4. 4. TCP Transmission: Controllo flusso, ritrasmissione se necessario
  5. 5. HTTP Response: Ricezione risposta con riassemblaggio pacchetti
  6. 6. Four-way Teardown: Chiusura connessione FIN → ACK → FIN → ACK

🎯 Concetti Chiave da Ricordare

🔒

TCP Reliability

TCP garantisce consegna affidabile attraverso acknowledgment, ritrasmissione e controllo di flusso. Ogni pacchetto viene confermato!

⚡

UDP Performance

UDP offre velocità massima senza overhead di affidabilità. Perfetto per streaming, gaming, DNS dove velocità > affidabilità.

🌐

IP Routing

IP instrada pacchetti attraverso reti complesse usando tabelle di routing. Ogni router decide il percorso ottimale.

📢

ICMP Control

ICMP fornisce messaggi di controllo e diagnostica. Ping usa ICMP Echo, traceroute usa TTL expiration.
