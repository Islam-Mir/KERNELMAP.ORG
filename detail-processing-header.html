PROCESSING HEADER

Intestazioni e Strutture Dati dei Processi

📋 INTESTAZIONI ELABORAZIONE

DESCRIZIONE:

Le Processing Header gestiscono i file di intestazione del kernel (<linux/sched.h>, <linux/sched/task_stack.h>) e le relative strutture dati che definiscono formalmente l'organizzazione, i campi e i metadati dei processi e dei thread in Linux.

CONFRONTO:

Come il registro anagrafico e i moduli ufficiali di un'organizzazione: definiscono formalmente i campi, i permessi, i tipi di dati e gli attributi di ogni entità registrata nel sistema, focalizzandosi sull'architettura statica dei descrittori anziché sul ciclo di vita dinamico.

🔍 Descrizione Tecnica

Le Processing Header definiscono i descrittori di processo e le interfacce strutturali del sottosistema di scheduling e gestione task del kernel Linux. A differenza di processes (incentrata sul ciclo di vita fork/exec/wait/exit e sugli stati operativi), queste intestazioni specificano l'architettura interna dei metadati tramite strutture come task_struct, mm_struct, signal_struct e le macro di accesso rapido.

• Process descriptors (task_struct) - Definizione dei campi di stato, PID, puntatori alle code e credenziali definiti nei file header del kernel

• Thread info blocks (<linux/sched/task_stack.h>) - Informazioni specifiche e stack del kernel per ogni thread

• Memory mapping fields (mm_struct) - Descrittori dello spazio di memoria virtuale e tabelle delle pagine

• Signal management (signal_struct) - Strutture dati per la ricezione e la gestione asincrona dei segnali

• Scheduling entities (sched_entity) - Parametri per CFS ed EEVDF (virtual runtime, pesi e priorità)

• Security contexts - Contesti di sicurezza e credenziali (UID, GID, capabilities)

• Nota sui kernel recenti: CFS è stato lo scheduler di default fino al kernel 6.5; dal 6.6 è affiancato/sostituito da EEVDF (Earliest Eligible Virtual Deadline First).

• Interazione: Forniscono al kernel le definizioni statiche e le macro necessarie per schedulare e gestire i task

⚙️ Operazioni Principali

Le Processing Header gestiscono l'architettura dei metadati dei processi attraverso macro e funzioni inline:

🔄 Strutture e Campi Chiave di task_struct

• unsigned int __state; - Stato corrente del processo (TASK_RUNNING, TASK_INTERRUPTIBLE, ecc.)

• pid_t pid, tgid; - Identificatore del processo e del gruppo di thread

• struct mm_struct *mm, *active_mm; - Descrittori dello spazio di memoria virtuale

• struct files_struct *files; - Tabella dei file descriptor aperti

• const struct cred *cred; - Credenziali di sicurezza (UID, GID, capabilities)

🎯 Macro di Accesso e Gestione Task

• current - Macro fondamentale definita negli header che restituisce il puntatore al task_struct del processo in esecuzione sulla CPU corrente

• task_pid_nr() - Estrae il PID numerico globale dal descrittore del task

• set_user_nice() - Aggiorna i parametri di priorità nice basandosi sulle strutture definite negli header

• for_each_process() - Iteratore per scorrere la lista circolare di tutti i processi del sistema

• dup_task_struct() - Alloca la struttura task_struct per un nuovo task

💾 Resource Tracking headers

• get_task_mm() - Ottiene il puntatore allo spazio di memoria del task

• get_task_cred() - Ottiene le credenziali di sicurezza definite nelle strutture

• task_lock() / task_unlock() - Meccanismi di blocco per la struttura task

• find_task_by_vpid() - Trova un task a partire dal PID visto dal namespace corrente

🛡️ Security Context Structures

• prepare_creds() - Prepara nuove credenziali basate sulle definizioni di header

• commit_creds() - Applica le nuove credenziali al task corrente

• override_creds() - Sostituisce temporaneamente le credenziali

• revert_creds() - Ripristina le credenziali originali

• validate_creds() - Valida la coerenza delle strutture di sicurezza

📋 Esempi Pratici

Come il kernel utilizza le definizioni delle Processing Header nel codice sorgente:

🔍 Accesso al Task Corrente nel Kernel

Nel codice del kernel, l'identificazione del processo attivo avviene tramite la macro current definita in <asm/current.h> e inclusa tramite le processing header:

struct task_struct *t = current;
printk(KERN_INFO "Processo corrente: %s [PID: %d]\n", t->comm, t->pid);

📄 Strutture Dati Definite nelle Header

  • task_struct - Contiene tutti i metadati descrittivi del processo
  • mm_struct - Gestisce la memoria virtuale e le tabelle delle pagine
  • sched_entity - Parametri di scheduling (vruntime, load, priorità)
  • signal_struct - Gestione dei segnali e dei relativi handler
  • files_struct - Gestione dei file aperti dal processo

💻 Nel Computer: Come Esaminare i Metadati?

Comandi Linux per esplorare le informazioni basate su queste strutture:

  • cat /proc/$$/status - Mostra stato, UID, GID e risorse del task
  • cat /proc/$$/sched - Parametri di scheduling estratti da sched_entity
  • cat /proc/$$/maps - Mappatura della memoria definita in mm_struct
  • cat /proc/$$/limits - Limiti di risorse associati al task

🎯 Caso Reale: Organizzazione dei Metadati

Quando il kernel gestisce una moltitudine di task concorrenti:

  1. Ogni task è rigidamente tipizzato tramite le definizioni di task_struct
  2. I puntatori incrociati collegano memoria (mm_struct), file (files_struct) e segnali (signal_struct)
  3. Le intestazioni garantiscono l'allineamento dei campi per ottimizzare la cache hardware
  4. Il context switch sfrutta la struttura salvando e ripristinando i registri descritti

⚙️ Modelli e Versioni del Kernel

  • CFS (Completely Fair Scheduler) - Scheduler basato su fairness e vruntime (default fino al kernel 6.5)
  • EEVDF (Earliest Eligible Virtual Deadline First) - Scheduler introdotto dal kernel 6.6 in poi
  • Real-time scheduling - SCHED_FIFO e SCHED_RR definiti nelle intestazioni
  • Task Grouping - Supporto per cgroups e isolamento risorse

✨ Caratteristiche

  • Modularità - Strutture dati estensibili e organizzate in file header dedicati
  • Efficienza - Layout ottimizzato per la cache della CPU e accesso rapido tramite current
  • Sicurezza - Separazione rigorosa dei contesti di credenziali e permessi
  • Scalabilità - Supporto per sistemi SMP con migliaia di task simultanei
  • Compatibilità - Strutture pronte per architetture multiple (x86, ARM, RISC-V)

🔗 Interazioni Chiave

Le Processing Header forniscono le fondamenta strutturali per tutti i sottosistemi:

⚙️ Scheduler Subsystem

• CFS / EEVDF - Leggono i campi di sched_entity per le decisioni di scheduling

• Load balancing - Utilizzano i metadati dei task per la distribuzione tra CPU

🧠 Memory Management

• Virtual memory - Collega task_struct a mm_struct e alle tabelle delle pagine

🔌 Interrupt System

• Context switching - Le intestazioni definiscono le routine di salvataggio dei registri nello stack

🔐 Security Framework

• Credentials - Gestione di UID, GID e capabilities tramite struct cred

📡 IPC Subsystem

• Signals - Strutture dati per la notifica asincrona e gestione handler

🛠️ API e Macro Principali

Funzioni e macro chiave definite nelle Processing Header del kernel:

⚙️ Accesso ai Task

struct task_struct *current;
Macro per ottenere il puntatore al processo in esecuzione sulla CPU corrente.

pid_t task_pid_nr(struct task_struct *tsk);
Restituisce il PID globale di un task.

struct task_struct *get_pid_task(struct pid *pid, enum pid_type type);
Risolve una struttura PID nel relativo task_struct.

🔐 Gestione Credenziali e Sicurezza

const struct cred *get_task_cred(struct task_struct *task);
Estrae le credenziali di sicurezza da un descrittore di task.

int capable(int cap);
Verifica se il task corrente possiede una specifica capability.

void put_cred(const struct cred *cred);
Rilascia il riferimento alle credenziali ottenuto con get_task_cred.

🎯 Concetti Chiave da Ricordare

📋

Definizione Strutturale

Le processing header definiscono la forma e i campi di task_struct, mm_struct e signal_struct utilizzati da tutto il kernel.

⚡

Costo del Context Switch

Il cambio di contesto ha un costo non trascurabile (alcuni microsecondi); le processing header ne ottimizzano salvataggio e ripristino dello stato.

🎯

La Macro current

Permette al codice del kernel di identificare istantaneamente il task in esecuzione accedendo a una variabile per-CPU o a un registro dedicato della CPU.
