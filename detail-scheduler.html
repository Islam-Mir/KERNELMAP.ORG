SCHEDULER

Schedulatore dei Processi

⏰ SCHEDULER

DESCRIZIONE:

Lo Scheduler è il componente del kernel che decide quale processo deve essere eseguito in ogni istante, gestendo l'allocazione dinamica del tempo CPU tra tutti i processi attivi.

CONFRONTO:

Come un arbitro in un torneo sportivo: decide chi gioca quando, per quanto tempo, e garantisce che tutti i giocatori abbiano una chance equa di vincere, bilanciando prestazioni e fairness.

🔍 Descrizione Tecnica

Lo Scheduler è il cervello del multitasking in Linux, implementando algoritmi complessi per distribuire equamente il tempo CPU tra processi concorrenti, bilanciando responsiveness e throughput. Immagina un direttore d'orchestra digitale che coordina centinaia di musicisti virtuali: ognuno ha il suo spartito (codice), strumento (CPU), e ritmo (priorità), ma il direttore garantisce che la sinfonia (sistema) suoni armoniosa.

• CFS (Completely Fair Scheduler) - Algoritmo principale basato su fairness e virtual runtime

• Real-time scheduling - Classi SCHED_FIFO e SCHED_RR per processi tempo-reale

• Priority management - Sistema di priorità nice da -20 a +19 per controllo utente

• Load balancing - Distribuzione processi tra CPU in sistemi multi-core

• Preemption - Interruzione processi per dare CPU a task più importanti

• Context switching - Salvataggio/ripristino stato processi durante cambi

• Interazione: Coordina con timer hardware, interrupt handler e memory manager per esecuzione efficiente

⚙️ Operazioni Principali

Lo Scheduler gestisce quattro aspetti fondamentali del multitasking, ciascuno critico per l'esecuzione concorrente:

🎯 Process Selection

• schedule() - Funzione principale chiamata per selezionare prossimo processo

• pick_next_task() - Sceglie task da eseguire tra quelli ready

• __schedule() - Implementazione interna del cambio di contesto

• context_switch() - Esegue effettivo cambio di contesto

• finish_task_switch() - Completa operazioni post-switch

⚖️ Fairness Management

• update_curr() - Aggiorna virtual runtime processo corrente

• check_preempt_curr() - Verifica se processo corrente deve essere preemptato

• resched_curr() - Marca processo per rischedulazione

• yield_to() - Cede CPU a processo specifico

• setscheduler() - Cambia politica scheduling processo

🔄 Load Balancing

• load_balance() - Bilancia carico tra CPU in sistemi multi-core

• find_busiest_queue() - Trova coda runqueue più carica

• detach_tasks() - Sposta task da CPU sovraccarica

• attach_tasks() - Attacca task a CPU target

• migrate_task() - Migra processo tra CPU

⏰ Timer Integration

• scheduler_tick() - Chiamata periodica dal timer per aggiornamenti

• task_tick_fair() - Aggiornamento contatori CFS

• task_tick_rt() - Gestione tick per processi real-time

• trigger_load_balance() - Avvia bilanciamento carico periodico

• account_process_tick() - Conteggia tempo CPU utilizzato

Quando lanci processi con priorità diverse, ecco come lo scheduler gestisce l'allocazione CPU:

🔍 Scheduling di Processi Interattivi vs Batch

1. Processo interattivo (editor) ottiene priorità dinamica più alta quando riceve input

2. Processo batch (compilazione) lavora in background con priorità più bassa

3. CFS bilancia automaticamente fairness moltiplicando tempo CPU per priorità

4. Context switch avviene ogni ~6-12ms per mantenere responsiveness

📄 Strutture Dati Chiave dello Scheduler

  • task_struct - Contiene tutte le informazioni di un processo: stato, priorità, virtual runtime, puntatori alla runqueue
  • runqueue (rq) - Coda dei processi pronti per esecuzione, organizzata per priorità
  • sched_entity - Entità di scheduling con virtual runtime e load weight
  • cfs_rq - Runqueue specifica del CFS con red-black tree per ordinamento

💻 Nel Computer: Come Vederlo?

Comandi Linux per esplorare lo scheduler:

  • ps -eo pid,ppid,pri,ni,stat,comm - Mostra priorità e stato processi
  • top - Monitora processi in tempo reale con colonne PR e NI
  • chrt -p PID - Mostra classe di scheduling di un processo
  • cat /proc/schedstat - Statistiche dettagliate dello scheduler
  • perf sched record - Registra eventi di scheduling per analisi

🎯 Caso Reale: Multitasking Sotto Carico

Quando fai vim documento.txt & gcc programma.c &:

  1. Entrambi processi entrano nella runqueue con priorità normale (nice=0)
  2. Vim ottiene boost dinamico quando digiti (I/O bound)
  3. GCC lavora steady con virtual runtime che cresce regolarmente
  4. Timer interrupt chiama scheduler_tick() ogni millisecondo
  5. Context switch mantiene vim responsive mentre gcc compila

⚖️ Classi di Scheduling

  • SCHED_NORMAL/CFS - Scheduling fair per processi normali (default)
  • SCHED_BATCH - Per processi CPU-intensive senza interazione
  • SCHED_IDLE - Priorità minima, eseguiti solo quando CPU idle
  • SCHED_FIFO - Real-time first-in-first-out senza preemption
  • SCHED_RR - Real-time round-robin con time slice
  • SCHED_DEADLINE - Real-time basato su deadline temporali

✨ Caratteristiche

  • Fairness - CFS garantisce equità nell'allocazione CPU
  • Scalability - Load balancing efficiente su sistemi multi-core
  • Real-time support - Scheduling deterministico per applicazioni critiche
  • Dynamic priority - Adattamento automatico priorità basato su comportamento
  • Preemption - Risposta rapida a eventi ad alta priorità

🔗 Interazioni Chiave

Lo Scheduler coordina con tutti i principali sottosistemi del kernel Linux:

⏰ Timer Subsystem

• High-resolution timers - Fornisce tick periodici per aggiornamenti scheduling

• NO_HZ - Disabilita timer su CPU idle per risparmio energetico

⚡ Interrupt System

• Timer interrupts - Segnalano fine time slice e necessità di rescheduling

• IPI (Inter-Processor Interrupts) - Coordinamento tra CPU per load balancing

🧠 Memory Management

• NUMA awareness - Tiene conto della topologia memoria nei sistemi multi-socket

• Memory pressure - Adatta comportamento scheduling basato su disponibilità memoria

🔌 Device Drivers

• Real-time drivers - Supporto per dispositivi che richiedono latenze garantite

• Power management - Coordinamento con stati di sospensione del sistema

🌐 Network Stack

• Network interrupts - Wake-up processi in attesa di dati di rete

• SoftIRQs - Elaborazione differita di pacchetti di rete

🛠️ API Principali

Queste sono le funzioni che controllano il comportamento di scheduling dei processi:

⚖️ Controllo Priorità

int nice(int inc);
Modifica la priorità nice del processo corrente (-20 a +19).

int setpriority(int which, id_t who, int prio);
Imposta priorità per processo, gruppo processi, o utente.

int getpriority(int which, id_t who);
Ottiene la priorità corrente di un processo.

⏰ Controllo Scheduling

int sched_setscheduler(pid_t pid, int policy, const struct sched_param *param);
Imposta la politica di scheduling (SCHED_FIFO, SCHED_RR, etc.).

int sched_getscheduler(pid_t pid);
Ottiene la politica di scheduling corrente.

int sched_yield(void);
Cede volontariamente la CPU ad altri processi.

🎯 Real-Time Scheduling

int sched_setparam(pid_t pid, const struct sched_param *param);
Imposta parametri real-time (priorità statica 1-99).

int sched_getparam(pid_t pid, struct sched_param *param);
Ottiene parametri real-time correnti.

int sched_rr_get_interval(pid_t pid, struct timespec *interval);
Ottiene il time quantum per processi SCHED_RR.

🔍 Esempi di Utilizzo Quotidiano

Quando lanci un processo in background:

  1. nice(10) - Abbassa priorità per non interferire con processi interattivi
  2. Il CFS assegna automaticamente virtual runtime basato sulla priorità
  3. Altri processi ottengono più tempo CPU relativamente
  4. Il processo lavora senza disturbare l'esperienza utente

Il controllo di priorità permette di bilanciare fairness e performance secondo le esigenze!

🎯 Concetti Chiave da Ricordare

⚖️

Fairness vs Performance

CFS bilancia equità (fairness) e prestazioni. Processi I/O-bound ottengono priorità dinamica più alta per responsiveness.

⏰

Virtual Runtime

Tempo CPU pesato per priorità. Processo con VR più basso ottiene CPU. Nice +10 = metà tempo CPU relativo.

🔄

Preemption

Interruzione processi per dare CPU a task più importanti. CFS permette preemption, RT classes hanno regole diverse.

⚡

Load Balancing

Distribuzione processi tra CPU in sistemi multi-core. Previene CPU idle mentre altre sono sovraccariche.
